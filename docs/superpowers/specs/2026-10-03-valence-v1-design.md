# Valence v1 — Design Spec

2026-10-03.

For v1 this spec replaces `Chem Lab Explorer - Design Document.md` (the "original doc"), except the original's "UI/UX and visual design" section, which still applies where this spec is silent. Where the two conflict, this spec wins. Everything else in the original is background and the long-term vision.

## 1. Purpose

Valence is an independent, browser-based molecule explorer and virtual general-chemistry lab for self-directed learners. It is a personal project with no connection to any school; it contains no course numbers, institution names, rooms, or storage locations.

v1 proves each of the app's four formats once:

1. A molecule explorer with atom and bond inspection over a curated library.
2. A quantitative lab: standardization of a base by titration.
3. A qualitative lab: ten reactions in aqueous solution.
4. One authored mechanism timeline: HCl + NaHCO₃.

Success for v1: a learner with no account can open the site, complete both labs in Guided or Challenge mode, have their results checked against the model, scrub the mechanism, and find their progress still there when they return in the same browser.

## 2. Decisions that differ from the original doc

| Topic | Original doc | v1 decision | Why |
| --- | --- | --- | --- |
| Scope | Seven labs across phases 2–4, 18 in total | Two labs, explorer, one mechanism | Smallest set that proves every format |
| Data rule | "No chemistry facts are hand-written" | Every chemistry value is hand-curated with a source and covered by a test | PubChem and NIST cannot supply solution colours, precipitate textures, aqueous enthalpies, pKa, or 3D for several molecules |
| Mixing | Rules give "correct results for combinations nobody planned" | The ten scripted stations only; two reagents per tube | About 8–10 of the 66 possible reagent pairs come out wrong under the five rules |
| Equations | Generated by the engine | Curated per station; the engine's result is tested against them | Writing formulas, states, and salt pairings in code for ten stations costs more than curating thirty equations |
| RDKit.js | In the browser | Not in the browser | It exposes no per-atom hybridization, oxidation state, or VSEPR; a fixed library needs none of it at runtime |
| Accounts | Supabase schema in phase 1, accounts in phase 5 | Deferred; guest-only | Nothing to sync until labs exist. A self-hosted Supabase already runs on the dev server when wanted |
| Repo | Monorepo, six packages | One Vite app with folders | One consumer in v1 |
| UI primitives | shadcn/ui on Radix | shadcn/ui on Base UI | Base UI is the current shadcn/ui default; the project follows current tool defaults |
| Web Workers | Simulation in workers | Main thread | The models are microseconds of arithmetic |
| Titration noise | Technique errors only | Technique errors plus small seeded glassware variation | Otherwise three good trials are identical and relative deviation teaches nothing |

## 3. Out of scope for v1

Accounts and any backend; the molecule builder; free mixing; the other 16 labs; RDKit in the browser; Web Workers; a dashboard beyond a list of labs with status; element pages; post-lab question sets; hazard data pulled automatically; numeric pH shown to the learner; reloading while offline; analytics of any kind.

## 4. Architecture

A single static TypeScript web app. No server.

Stack: TypeScript, Vite, React, Tailwind v4, shadcn/ui, Three.js via React Three Fiber, Vitest.

```
src/
  chem-data/    curated JSON, TypeScript types, derive functions, validator
  engine/       seeded RNG, ion bookkeeping, reaction rules, pH solver, titration model
  mechanisms/   authored timeline data + pure state function
  app/          React UI, 3D scenes, lab benches, routing, progress storage
scripts/        build-time helpers (fetch PubChem SDFs once, generate mechanism keyframes)
```

Rules:

- `engine/`, `chem-data/`, and `mechanisms/` never import React, Three.js, or the DOM. An ESLint `no-restricted-imports` rule enforces this.
- `engine/` never calls `Math.random` or reads the clock (lint rule). All variation comes from a seeded generator (mulberry32) passed in explicitly.
- `fetch` and `XMLHttpRequest` are banned in `src/` by lint. All chem-data is bundled; the Inter font is self-hosted. "Offline" means no network requests after first load.
- Every engine model has Vitest tests before its UI is built.
- `app/` depends on the other three folders; they never depend on `app/`.
- Routing uses a hash router, so deep links work on any static host without rewrite rules.
- React Three Fiber is used only in Explore and Learn. Lab benches are 2D SVG with DOM controls.

The app has three areas reached from a collapsible left rail: **Explore**, **Lab**, **Learn**. The home page lists the two labs and the mechanism with status (not started, in progress, completed).

## 5. Chemistry data

### 5.1 The rule

Every chemistry value shown to a learner or used by a model is stored in `chem-data/` or `mechanisms/` with a source. Sources are listed once in `chem-data/sources.json` as `{ id, url, citation }`.

- A record's `sourceId` covers every value in it unless a value carries its own.
- Values that section 5.2 cites individually (experimental lengths and angles, thermodynamic values, observation rows) are stored as `{ value, sourceId }`.
- Three kinds of field are exempt from citation, and the schema marks which is which: authored structure (formal charge, lone pairs, bond orders, 2D layout); values derived in TypeScript; and model parameters, stored as `{ value, rationale }`.

The validator runs in tests and in the build, over both folders, and fails when:

1. a field that requires a source has none, or names a `sourceId` that does not exist;
2. an ID referenced by a station or mechanism does not exist;
3. a molecule file's coordinates look like a 2D drawing: any bond to hydrogen shorter than 0.80 Å, or any bond between two non-hydrogen atoms shorter than 1.05 Å;
4. any authored prose string (chem-data text, mechanism text, lab primers) matches an institution-specific pattern: a location word (`room`, `building`, `cabinet`, `shelf`, `stockroom`) followed by a number or letter-number code; a course-number shape (two to four letters followed by three or four digits, excluding text that follows `CID`, `CAS`, or a citation year); or a name from a configurable list. The validator's tests pin this: "room temperature", "building block", "CID 962", and "NIST 2022" must pass; "Room 214", "CHEM 1411", and "cabinet B3" must fail.

PubChem CIDs are stored for identity and outbound links. Nothing is fetched at runtime.

In the UI, each inspector card, station result, and energy panel has a "Sources" control listing the citations and links for the values it shows.

### 5.2 Sources

| Data | Source |
| --- | --- |
| 3D coordinates for the Basics and VSEPR showcase groups (section 6.1) | Built by a script from cited experimental bond lengths and angles (NIST CCCBDB, or a cited diffraction value where CCCBDB has none), so the model, the measure tool, and the card agree. Includes BF₃, SF₆, XeF₄, and PCl₅, which have no PubChem 3D record |
| 3D coordinates for all other molecules and polyatomic ions | PubChem 3D SDF, fetched once by a script and committed. The script requests `record_type=3d` and fails on HTTP 404; it never falls back to a 2D record. Labelled "computed model (MMFF94s, PubChem3D)" |
| Element data: mass, electronegativity, configuration, ionization energies | CRC Handbook |
| Ionic radii; van der Waals radii | Shannon 1976; Bondi 1964 |
| Formation enthalpies and free energies of aqueous ions and of NaHCO₃(s) | NBS tables (Wagman 1982) |
| True H₂CO₃ acidity, CO₂ hydration equilibrium, dehydration rate | Primary literature (for example Adamczyk et al., *Science* 2009; Wang et al., *J. Phys. Chem. A* 2010) |
| pKa (including phenolphthalein), Kw | CRC Handbook or IUPAC compilations |
| Solubility per ion pair; activity series; Henry's constant for CO₂ | CRC Handbook, one citation per value |
| Solution heat capacity and density at station 8 | Treated as water (4.18 J/g·K, 1.00 g/mL); cited and labelled "idealised" |
| Indicator solution strength and drop volume | Curated, cited |
| MO orbital order for O₂ and N₂ | One cited textbook |
| Precipitate colour and texture, solution colours, odours, solid reagent appearance | Curated observation table, one citation per row |
| Hazards | One hand-picked GHS classification per reagent from its PubChem record, labelled "hazards of the pure substance", plus a curated note for the concentration used |

### 5.3 Shapes

**Reagent:** `id`, `name`, `formula`, `pubchemCid`, `form` (solution, solid, metal), `molarity` (solutions), `molarMass` (solids and metals), `appearance` (solids and metals), `ions` (species IDs and stoichiometric ratio), `hazards`, `sourceId`. Hazards are shown on the reagent's bottle card.

**Species** (ions and products): `id`, `formula`, `composition` (element counts), `charge`, `state`, optional `solutionColor` (name and hex), thermodynamic values where a model needs them.

**Observation row:** product `id`, `color`, `texture`, `odor`, `sourceId`.

**Station:**

- `id`, the two reagent IDs, and `amounts` (mL for each solution, g for each solid or metal). Amounts are fixed; the learner does not choose them.
- `observationTools`, and for each tool and tool position the outcome shown.
- `equations`: curated molecular, complete ionic, and net ionic equations with states (all three null at station 5).
- `expected`: `{ precipitate: species ID or none, precipitateColor, liquidColor, gas: species ID or none, odor, temperature: none | warm | hot, toolResults }`.
- `paletteSpecies` (correct species plus distractors), `hints`, `notes`.

**Molecule:** `id`, `name`, `pubchemCid`, `topic`, optional `variantGroup` and `variantLabel` (for neutral and zwitterion forms), atoms (element, 3D position, 2D position, formal charge, lone pairs), bonds (atom pair, integer order in the Kekulé form, aromatic flag, optional `resonanceNote`), `geometrySource` (PubChem computed, ideal VSEPR, or cited experimental), optional experimental lengths and angles, `sourceId`.

Molecule files hold curated inputs only. Oxidation state, steric number, hybridization, and VSEPR geometry are derived by pure functions in `chem-data/derive.ts` and are not stored.

**MO diagram:** molecule ID, ordered levels (label, degeneracy, electron count, bonding or antibonding), `sourceId`.

## 6. Explorer

### 6.1 Library

The library is the 31 entries below. Glycine and alanine each have a neutral and a zwitterion structure file (33 files in total), shown as one library entry with a form toggle.

- **Basics (8):** H₂O, CO₂, NH₃, CH₄, O₂, N₂, HCl, H₂O₂.
- **VSEPR showcase (5):** BF₃, SO₂, SF₆, XeF₄, PCl₅.
- **Organic functional groups (11):** ethane, ethene, ethyne, ethanol, acetic acid, acetone, formaldehyde, methylamine, ethyl acetate, acetamide, benzene.
- **Biomolecules (4):** β-D-glucopyranose (CID 64689), glycine (zwitterion CID 5257127), alanine (zwitterion CID confirmed when the fetch script is written), urea.
- **Mechanism species (3):** H₃O⁺, HCO₃⁻, H₂CO₃.

No salts in the library: ionic compounds are not molecules. PCl₅ carries a "gas-phase structure" note and separate axial and equatorial bond lengths.

### 6.2 Views

Ball-and-stick, space-filling (van der Waals radii), wireframe, and 2D Lewis. Double and triple bonds render as parallel cylinders; aromatic bonds render as delocalised. The 2D Lewis view is custom SVG drawn from the curated 2D positions and lone-pair counts.

### 6.3 Inspectors

Inspectors open when an atom or bond is selected. Beside the canvas, a DOM list of atoms and bonds shares selection with it, so the inspectors and the measure tool work by keyboard.

**Atom card**, base layer: symbol, atomic number, mass, electronegativity, valence electrons, formal charge, oxidation state, hybridization, VSEPR geometry. Expanded layer: electron configuration, ionization energies, atomic and ionic radii.

**Bond card:** length, order, polarity as Pauling electronegativity difference (labelled "a rough guide"), σ/π composition. Aromatic bonds show "aromatic (delocalised), order 1.5". A bond with a `resonanceNote` shows it: the carboxylate C–O bonds of the zwitterions and the two unprotonated C–O bonds of HCO₃⁻ read "one of two equivalent resonance structures; effective order 1.5".

Derived values:

- **Oxidation state:** valence electrons minus (lone-pair electrons + bonding electrons assigned to the atom). Each bond's electrons go to the more electronegative atom (Pauling) and are split equally between atoms of the same element.
- **VSEPR geometry:** shown only for atoms bonded to two or more atoms; other atoms show "terminal atom". Computed from the steric number (bonded atoms + lone pairs) by lookup. An atom covered by the resonance override below does not count its delocalised lone pair as a domain, so amide and urea nitrogens are trigonal planar.
- **Hybridization:** from the steric number. Resonance override: a lone-pair atom adjacent to a π system (amide N, urea N, carboxylic and ester O) is sp². Hydrogen shows "none (1s)". For steric numbers 5 and 6 the card reads "sp³d (textbook label; real d-orbital involvement is negligible)" or the sp³d² equivalent.
- **Lengths and angles:** measured from the stored coordinates and labelled with `geometrySource`. Flexible molecules (ethanol, glucose, ethyl acetate) carry the note "one conformer of many".

**Measure tool:** select three atoms for a bond angle, four for a dihedral.

### 6.4 Valence display levels

1. A Bohr diagram of the selected atom, with shell counts from the stored electron configuration, labelled "Bohr model: a simplified picture".
2. Lewis dots and lone pairs.
3. Hybrid orbital lobes for sp, sp², sp³ only; molecular orbital diagrams for O₂ and N₂ only. The O₂ diagram carries a callout that the Lewis structure shows all electrons paired while the MO diagram shows two unpaired.

Lone-pair directions for levels 2 and 3 come from one pure function of the atom's bond vectors and its ideal electron geometry, with an optional per-atom override.

Hybrid lobes are the last item of the Explorer phase and the first to cut if the phase runs long.

### 6.5 Acceptance

- A test asserts the bundled registry contains every library ID and that every file passes the validator.
- The validator checks every atom's stored formal charge against valence electrons minus lone-pair electrons minus the sum of bond orders.
- Oxidation states sum to each species' charge.
- A hand-written expected-values table in the test suite covers every atom of the Basics, VSEPR, and Mechanism groups and every non-hydrogen atom of the rest (oxidation state, hybridization, VSEPR geometry; order per bond). It includes: H₂O₂ (O is −1); acetamide and urea N (sp², trigonal planar); a terminal atom (no geometry shown); SO₂ with the Lewis structure used stated (S is +4, bent); SF₆ (octahedral); XeF₄ (square planar); PCl₅ (trigonal bipyramidal; angles 90°, 120°, 180°); benzene (all bonds aromatic).
- For molecules whose `geometrySource` is cited experimental, lengths measured from the stored coordinates match the cited values within 0.01 Å and angles within 1°.
- Lone-pair directions for H₂O and NH₃ match the tetrahedral positions within 5°. The O₂ diagram has two unpaired electrons and bond order 2; N₂ has bond order 3.
- `describeMolecule` (the text description for screen readers) is tested for three molecules.

## 7. Titration lab

### 7.1 Setup

The lab opens with a short concept primer: the ideas, equations, and vocabulary it needs, written for a reader with no chemistry background. The primer explains why NaOH needs standardizing: the solid absorbs water and CO₂ from air, so it cannot be weighed accurately.

The learner titrates a 25.00 mL pipetted aliquot of standardized HCl (in the flask) with ~0.1 M NaOH from a 50 mL burette, using phenolphthalein, and calculates the NaOH molarity.

**Seeded values.** `app/` generates a 32-bit seed when the lab is first started, stores it, and shows it in the notebook. The seed fixes, when the lab is created and never during play:

- the HCl label, 0.0850–0.1050 M, shown to four decimal places;
- the hidden true NaOH concentration, 0.0950–0.1050 M;
- per trial, the pipette's delivery: 25.00 mL plus a uniform offset in [−0.03, +0.03] mL (the learner calculates with the nominal 25.00 mL);
- per trial, the burette level after filling: uniform in [0.00, 2.00] mL at 0.001 mL resolution, so the meniscus generally sits between marks.

The burette is graduated every 0.1 mL and read by estimation to 0.01 mL. No other noise is added. These ranges keep every titre between 20.2 and 27.7 mL. The same seed and the same learner actions always give the same readings and expected answer. "Restart lab" draws a new seed after confirmation.

### 7.2 Workflow

1. Select the HCl bottle and record its molarity.
2. Condition the burette with NaOH, fill it, clear the tip bubble, read the initial volume.
3. Rinse the pipette with HCl, then pipette the aliquot.
4. Add 2–3 drops of phenolphthalein.
5. Titrate to a faint pink that persists; read the final volume.
6. Refill the burette and record a new initial reading before each further trial (no re-conditioning needed).

The notebook shows average and relative deviation only after the learner has entered their own values.

**Stopcock:** closed, stream, dropwise (0.05 mL), half-drop (0.025 mL). In stream mode the app sends fixed-volume additions on a timer; the engine sees only volumes. Delivery stops at the 50.00 mL mark; a trial that reaches it before the endpoint is invalid with the message "burette ran out; refill before starting a trial".

**Plume.** Each addition makes a local pink plume that fades on swirling and lingers longer near the endpoint. Its intensity and fade time come from an engine value. The same value drives a status line ("pink fades at once", "pink fades slowly", "pink persists"), which is the only cue under reduced motion. Persistence is checked by a "swirl and wait" action that advances simulated time; there is no real 30-second wait.

**Modes.** Guided shows a step checklist, warns before a skipped technique step (conditioning, tip bubble, pipette rinse), prompts a re-read when a typed reading is more than 0.02 mL from the true meniscus, and shows a "slow down" hint within 1.00 mL of equivalence. It never shows the expected titre or molarity. Challenge shows none of these; skipped steps and misreadings carry into the result and are named in the post-trial feedback.

### 7.3 Model

**pH solver.** One charge-balance equation solved by bisection on pH, covering strong, weak, and polyprotic species. It returns ideal-solution pH (no activity corrections). v1 shows no numeric pH to the learner.

**Endpoint colour.** The flask's species list includes the indicator itself (a weak acid, in the amount delivered by the learner's drops) and dissolved CO₂ at air-equilibrium concentration. Both buffer the jump at equivalence, as they do in a real flask.

- Colour intensity is proportional to the concentration of indicator in its pink form: pink fraction × indicator moles ÷ flask volume. More indicator drops therefore give a deeper pink.
- Faint pink begins at `faintPinkConcentration`, a model parameter (starting value 3×10⁻⁶ M). The endpoint is persistent when the fully mixed flask is at or above it.
- The indicator's pKa, the indicator solution strength, the drop volume, Henry's constant, and the atmospheric CO₂ fraction are cited constants and are never adjusted to pass tests. Only `faintPinkConcentration` is tuned.

Proving the endpoint acceptance test in 7.4 is the first task of the titration phase. If it cannot pass with cited constants, dissolved CO₂ is removed from the flask model and this spec is updated.

**Trial states.**

- *Invalid:* the delivered volume is more than 0.10 mL (two drops) past the true equivalence volume (shown dark pink, labelled "overshot"), or the burette ran out. Must be repeated.
- *Valid and passing:* a persistent endpoint was reached and the learner's calculated NaOH molarity is within ±1.0% of the seeded NaOH concentration.
- *Valid and failing:* a persistent endpoint was reached but the molarity is outside ±1.0%. The trial shows its signed percent error only.

The learner may run any number of trials. The lab is completed when three trials have passed; the true molarity is shown on completion. Relative deviation is the mean absolute deviation divided by the mean, in parts per thousand; it is displayed, not graded.

**Technique errors.** Each is a deterministic consequence of what the learner did or skipped. Magnitudes are model parameters, deliberately exaggerated so each error fails grading on its own at every seed; feedback names the cause.

| Error | Effect in the model | Result |
| --- | --- | --- |
| Unconditioned burette | NaOH in the burette diluted by 2.0% | Titre reads high; calculated molarity low |
| Tip bubble not cleared | 0.60 mL bubble escapes during the first 5 mL delivered, so the recorded volume exceeds the delivered volume | Calculated molarity low |
| Pipette not rinsed with HCl | Aliquot diluted by 2.0% | Titre reads low; calculated molarity high |
| Meniscus misread | Reading typed to 0.01 mL, compared with the true position within ±0.02 mL | Carried into the result (Challenge) or re-read prompt (Guided) |
| Distilled water added to the flask | Dilutes the flask only | No change in the result (a misconception check) |

### 7.4 Acceptance

- **Solver:** within 0.01 pH of an independently computed exact solution, with constants pinned in the test, for 0.0100 M HCl (2.00), 0.10 M acetic acid (2.87–2.88), 0.10 M H₃PO₄ (about 1.63), 0.10 M acetic acid with 0.10 M sodium acetate (pH equals the pinned pKa), and 1×10⁻⁸ M HCl (6.98).
- **Titration curve** (HCl and NaOH only, no indicator or CO₂): within 0.01 pH of the closed-form strong acid/strong base solution at every point more than 0.5 mL from equivalence; the volume at which the computed pH crosses 7.00 is within 0.01 mL of the stoichiometric value.
- **Endpoint:** a careful run is stream to 2.00 mL before equivalence, dropwise to 0.20 mL before, then half-drops until persistent. For seeds 1–100, at 2 and at 3 drops of indicator, the flask is below `faintPinkConcentration` at every addition before equivalence, the persistent endpoint appears between V_eq and V_eq + 0.05 mL, and the trial is not flagged as overshoot.
- **Grading:** a calculated molarity at +0.9% passes and at +1.1% fails.
- **Technique errors:** for seeds 1–100, each of the first three errors alone moves the calculated molarity in the stated direction by more than 1.5%; adding distilled water to the flask changes it by 0.
- **Reproducibility:** the same seed and the same learner actions give identical readings and expected answer.

## 8. Aqueous reactions lab

The lab opens with a short concept primer covering solubility, the three equation forms, and safe observation (wafting).

### 8.1 Engine

For a station, the engine:

1. Tallies moles of every ion and solid present from the station's fixed amounts and the reagents' concentrations and molar masses.
2. Applies the rules. Each acts on dissolved ions and on solids:
   - insoluble ion pairs form a precipitate (from a per-ion-pair solubility table);
   - H⁺ with CO₃²⁻ or HCO₃⁻ forms CO₂ gas;
   - NH₄⁺ with OH⁻ forms NH₃;
   - H⁺ with OH⁻ forms water and releases heat;
   - a metal with H⁺, by the activity series, forms H₂ gas and the metal ion and releases heat. The activity series holds only the entries v1 uses (Mg above H₂).
3. Respects the limiting reagent. Spectator ions keep their colour: Cu²⁺ stays blue over white BaSO₄ whichever reagent is limiting.
4. If no rule fires, reports no reaction; only the blended reagent colours show.

A tube holds exactly two reagents with no later additions, so one ordered pass is sufficient. The engine exposes only the ten stations; it has no entry point for arbitrary pairs.

**Engine output:** which rule fired, product IDs and amounts, the limiting reagent, the temperature rise, and which coloured ions remain. The temperature rise assumes no heat loss and water's heat capacity and density, and is labelled idealised.

**Curated per station:** the three equations, the liquid colour name, and colours, textures, and odours (from the observation table). In ionic equations only dissolved strong electrolytes are split into ions; solids (CaCO₃, Mg, precipitates), H₂O, gases (CO₂, H₂), and NH₃ are written as whole formulas.

### 8.2 Stations

Stations 1–6, 8, and 9 use 2.0 mL of each solution.

| # | Reagents | Expected result | Tool |
| --- | --- | --- | --- |
| 1 | FeCl₃ 0.5 M + NaOH 1 M | Rust-brown gelatinous Fe(OH)₃ precipitate; liquid stays yellow-orange (OH⁻ is limiting) | Eye |
| 2 | Na₂CO₃ 0.5 M + CuSO₄ 0.5 M | Blue-green precipitate | Eye |
| 3 | Na₂CO₃ 0.5 M + NiCl₂ 0.5 M | Pale green precipitate | Eye |
| 4 | BaCl₂ 0.5 M + CuSO₄ 0.5 M | White BaSO₄; liquid stays blue | Eye |
| 5 | CoCl₂ 0.5 M + FeCl₃ 0.5 M | No reaction; colours only blend | Eye |
| 6 | NH₄NO₃ 0.5 M + NaOH 1 M | Ammonia odour; moist red litmus held above the liquid turns blue | Waft, litmus |
| 7 | CaCO₃ 0.10 g + HCl 1 M, 3.0 mL | Fizzing; solid dissolves completely (acid in excess) | Eye |
| 8 | HCl 6 M + NaOH 6 M | Nothing visible; tube gets hot (about 40 °C rise) | Touch or thermometer |
| 9 | CoCl₂ 0.5 M + AgNO₃ 0.1 M | White AgCl precipitate; liquid stays pink (Ag⁺ is limiting) | Eye |
| 10 | Mg 0.012 g + HCl 3 M, 5.0 mL | H₂ bubbles; ribbon dissolves; tube warms (about 11 °C rise); trapped gas pops with a lit splint | Lit splint, touch |

This table is the readable summary; each station's structured `expected` record is the test oracle.

Station notes:

- **2 and 3:** the graded net ionic equation is the simple carbonate (M²⁺ + CO₃²⁻ → MCO₃). An expanded note says the solid that really forms is a basic carbonate, such as Cu₂(OH)₂CO₃.
- **5:** the no-reaction control; the engine must not invent a product.
- **6:** the litmus tool has two positions. In the liquid it turns blue from excess NaOH alone, which proves nothing; held moist in the vapour it shows ammonia. Sniffing directly instead of wafting triggers a safety note. No vigorous bubbling is shown: ammonia is very soluble.
- **8:** only detectable by temperature. The touch tool carries a caution that the tube is hot and the contents corrosive.

### 8.3 Learner input and checking

**Observations** are recorded with structured choices, not free text. The form shows only the fields the station's tools can observe; other fields are neither asked nor graded. An observation is correct when every shown field equals the station's `expected`.

**Equations.** For each station the learner enters molecular, complete ionic, and net ionic equations with a species palette: they pick species offered for that station (including distractors), set coefficients and states, and place each on the reactant or product side. The palette always offers "No reaction", which is the correct answer at station 5. An equation is correct when the species on each side match the curated equation, each state is in that species' accepted list (NH₃ accepts aq or g), and the coefficients are proportional. No free-text equation parsing.

**Guided mode** shows hints and the expected observations up front. **Challenge mode** hides them until the learner records their own, then checks.

The lab is completed when all ten stations have correct observations and equations. Attempts are unlimited. Progress is saved per station.

### 8.4 Acceptance

- For each station, the engine's output agrees with the station's `expected` record: precipitate ID, gas ID, temperature class, remaining coloured ions; and its fired rule and product IDs agree with the curated net ionic equation. Station 5 returns no reaction.
- The limiting reagent matches the oracle: OH⁻ at station 1, Ag⁺ at station 9, the solid fully consumed at stations 7 and 10.
- Computed temperature rise: 35–45 °C at station 8; 8–14 °C at station 10.
- Every curated equation balances in atoms and charge, and no net ionic equation has a species unchanged on both sides.
- The equation checker accepts doubled coefficients and rejects a distractor species.
- `describeStationResult` (the text description of what is seen) is tested for every station.

## 9. Mechanism timeline

### 9.1 Model

A mechanism is authored choreography. The scene state is a pure function `state(mechanism, t)` of the scrub position `t` in [0, 1]: atom positions, bond orders, electron-pair paths, active species, energy cursor, camera target, and explanation text. Scene components draw from `state` only, with no smoothing between frames, so scrubbing in either direction gives identical frames. The learner-controlled camera is the one exception.

**Data.** A mechanism has a fixed actor list (one stable `atomId` and element per atom for the whole timeline) and a keyframe at every step boundary, giving every actor's position and the bond list with orders. `state` interpolates positions between keyframes with a named easing; a bond whose order changes is drawn as partial. Keyframes are generated by a build script from a small authored file that places library species by rigid transform and maps library atom indices to actor IDs. Only the water molecules that take part in a step are explicit; bulk solvent, hydration shells, and the bubble stage are a non-atomistic backdrop.

**Step record:** time range on the track, bonds broken, bonds formed, electron paths, `deltaH` and `deltaG` (standard-state, each cited or marked as derived), optional `activationG` (cited, or the marker "schematic"), camera target, explanation text at `intro` and `expanded` depth, real timescale label, optional prediction question.

**Features:** chapters with deep links (`?step=proton-transfer`); a non-linear track with each chapter's real timescale as a label; camera auto-framing that the learner can override and that resumes on release; beaker bookends at the start and end. The timeline is a native range input and announces on chapter change only.

**Modes.** The mechanism has the same Guided/Challenge selector as the labs. Challenge pauses before key steps to ask "What happens next?"; Guided skips the pauses. The mechanism is completed when the learner has reached `t` = 1.

### 9.2 HCl + NaHCO₃ → NaCl + H₂O + CO₂

Solid NaHCO₃ is added to hydrochloric acid. Track order: beaker bookend, prologue, steps 1–4, beaker bookend.

- **Prologue** (chapter `prologue`, deep-linkable, labelled "before mixing", no energy values): what is already in the bottle. Hydrochloric acid is fully ionised: H₃O⁺ and hydrated Cl⁻.
1. **Dissolving:** NaHCO₃ separates into hydrated Na⁺ and HCO₃⁻. Timescale: seconds, depending on particle size and stirring.
2. **Proton transfer:** H₃O⁺ gives its proton to HCO₃⁻, forming H₂CO₃. Timescale: picoseconds to nanoseconds.
3. **Decomposition:** H₂CO₃ splits into H₂O and dissolved CO₂ through a water-relayed proton shift. Timescale: tens of milliseconds; the slow step.
4. **Gas escapes:** dissolved CO₂ gathers into bubbles and leaves; Na⁺ and Cl⁻ remain as spectators. Timescale: seconds.

**Energies.** The overall process is NaHCO₃(s) + H⁺(aq) → Na⁺(aq) + H₂O(l) + CO₂(g), with ΔH = +31.4 kJ/mol and ΔG = −42.4 kJ/mol at 298 K from the NBS tables.

- In the NBS tables, "H₂CO₃(aq)" means CO₂(aq) + H₂O. That entry must not be used for the true H₂CO₃ molecule shown in steps 2 and 3.
- Step 2 uses the cited true pKa of H₂CO₃. Step 3 is the NBS total for H⁺ + HCO₃⁻ → CO₂(aq) + H₂O minus step 2, labelled as derived.
- If no separate enthalpy for true H₂CO₃ can be cited, the enthalpy curve shows steps 2 and 3 as one segment.
- A barrier with no citation is drawn schematically and labelled "not to scale".
- Step 1's ΔG is slightly positive at standard state. It carries the note "slightly uphill at 1 M; it dissolves because the acid removes HCO₃⁻ as it forms".

The energy panel plots free energy as the main curve with enthalpy alongside. Its note reads: heat is absorbed in dissolving the solid and releasing the gas; the reaction proceeds because escaping gas increases entropy. This leads into Gibbs free energy.

Monatomic ions (Na⁺, Cl⁻) are drawn as spheres sized by cited ionic radii. Polyatomic species use the library's 3D records.

The literature values for true H₂CO₃ are identified and cited before the mechanism phase's plan is written.

### 9.3 Acceptance

- **Continuity:** at every step boundary, `state` just before and just after gives the same atom positions within a small tolerance.
- **Bond bookkeeping:** each bond in a step's bonds-broken exists before the step and each bond in bonds-formed does not; each step's bond list at its end equals the list at its start, minus bonds broken, plus bonds formed. The set of atoms and the total charge of the scene are identical at every chapter boundary, and every species' connectivity there matches its library record.
- **Energies:** the summed step `deltaH` and the summed step `deltaG` (steps 1–4) equal +31.4 and −42.4 kJ/mol within 0.5 kJ/mol.
- **Deep links:** each chapter's link opens at that chapter's start.

## 10. Progress

Guest-only. Progress is stored in `localStorage` as JSON. Each lab, the mechanism, and preferences have their own entry with its own version, so a change to one resets only that one.

- **Per lab:** seed, mode, status, recorded readings and observations, answers, and the current trial's engine state as plain data. Titration progress is saved after every learner action, including each stopcock close, so a reload resumes the current trial at the saved delivered volume. Aqueous progress is saved per station.
- **Mechanism:** mode, last position, answered predictions.
- **Preferences:** theme and reduced motion (each System, On, or Off; System is the default and follows the operating system), valence display level.

Stored records are plain data with no browser-specific types, so the same shapes can later be written to a database unchanged. If an entry fails to parse or has an unknown version, that entry starts fresh and the old value is kept under a backup key instead of being deleted.

A settings page offers "export my progress" (downloads the JSON) and "clear my progress".

## 11. UI and accessibility

As in the original doc: calm, card-based layout; the 3D viewport or lab bench in the centre; inspector and notebook docked right; mechanism timeline docked along the bottom; light and dark themes; Inter with tabular numerals; design tokens as CSS variables in the Tailwind theme; a Ctrl+K command palette over molecules, labs, and the mechanism.

Accessibility is designed toward WCAG 2.1 AA:

- Full keyboard operation. Explore works through the DOM atom and bond list (section 6.3). Lab tools are DOM controls. The timeline is a native range input.
- Colour is never the only signal: every colour observation also has a text label, and the titration plume has a status line.
- Text descriptions of 3D scenes and station results come from pure functions (`describeMolecule`, `describeStationResult`) tested in Vitest.
- The meniscus text alternative gives the two bracketing graduations and a rough position between them, not the reading itself.

Target screens: 1366×768 first, scaling up. Tablets fully supported. On viewports narrower than 768 px, Explore and Learn work; a lab page shows its primer, the notebook of any saved run (read-only), and a notice to continue on a larger screen, and the bench is not shown.

## 12. Documentation for institutional reviewers

Valence is made for any learner, not for a particular institution. The repository is expected to become public, and a school or college may still want to review it before pointing students to it. The documentation therefore includes one clearly labelled section for each department that might do so, written as plain statements so the decision is easy. The sections are institution-agnostic: none names or targets a specific school.

- **IT and security:** static site, no server, no login, no install; what the browser stores; how to self-host; browser requirements. On a shared computer, saved progress is visible to the next person using the same browser profile; the docs say so and point to "clear my progress".
- **Legal and privacy:** no accounts, no personal data collected, no analytics, nothing transmitted to any server, so the app creates and holds no education records. FERPA, COPPA, and GDPR are addressed in those factual terms. Licence and third-party data attributions.
- **Accessibility services:** what has been tested against WCAG 2.1 AA and what has not.
- **Finance and procurement:** free, MIT-licensed, no contract, no vendor, no support agreement.
- **Faculty and curriculum:** which labs exist, what each teaches, how answers are checked, where every chemistry value is sourced.
- **Lab safety:** Valence supplements bench labs and does not replace safety training; hazard information describes the pure substance.

Rules: state only what is true and tested when written. The docs never say "FERPA compliant" (that determination belongs to the institution) and make no WCAG conformance claim before an audit. They keep the statement that Valence is independent, with no vendor relationship. Each section is written as its features land.
