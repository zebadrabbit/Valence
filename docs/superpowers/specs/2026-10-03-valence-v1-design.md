# Valence v1 — Design Spec

2026-10-03.

For v1 this spec replaces `Chem Lab Explorer - Design Document.md` (the "original doc"), except the original's "UI/UX and visual design" section, which still applies where this spec is silent. Where the two conflict, this spec wins. Everything else in the original is background and the long-term vision.

## 1. Purpose

Valence is an independent, browser-based molecule explorer and virtual general-chemistry lab for self-directed learners. It is a personal project with no connection to any school; it contains no course numbers, institution names, rooms, or storage locations.

v1 proves each of the app's four formats once:

1. A molecule explorer with atom and bond inspection over a curated library.
2. A quantitative lab: standardization of a base by titration.
3. A qualitative lab: ten reactions in aqueous solution.
4. One authored mechanism timeline: HCl + NaHCO₃.

Success for v1: a learner with no account can open the site, complete both labs in Guided or Challenge mode, have their results checked against the model, scrub the mechanism, and find their progress still there when they return in the same browser.

## 2. Decisions that differ from the original doc

| Topic | Original doc | v1 decision | Why |
| --- | --- | --- | --- |
| Scope | Seven labs across phases 2–4, 18 in total | Two labs, explorer, one mechanism | Smallest set that proves every format |
| Data rule | "No chemistry facts are hand-written" | Every chemistry value is hand-curated with a source and covered by a test | PubChem and NIST cannot supply solution colours, precipitate textures, aqueous enthalpies, pKa, or 3D for several molecules |
| Mixing | Rules give "correct results for combinations nobody planned" | The ten scripted stations only; two reagents per tube | About 8–10 of the 66 possible reagent pairs come out wrong under the five rules |
| Equations | Generated by the engine | Curated per station; the engine's result is tested against them | Writing formulas, states, and salt pairings in code for ten stations costs more than curating thirty equations |
| RDKit.js | In the browser | Not in the browser | It exposes no per-atom hybridization, oxidation state, or VSEPR; a fixed library needs none of it at runtime |
| Accounts | Supabase schema in phase 1, accounts in phase 5 | Deferred; guest-only | Nothing to sync until labs exist. A self-hosted Supabase already runs on the dev server when wanted |
| Repo | Monorepo, six packages | One Vite app with folders | One consumer in v1 |
| UI primitives | shadcn/ui on Radix | shadcn/ui on Base UI | Base UI is the current shadcn/ui default; the project follows current tool defaults |
| Web Workers | Simulation in workers | Main thread | The models are microseconds of arithmetic |
| Titration noise | Technique errors only | Technique errors plus small seeded glassware variation | Otherwise three good trials are identical and relative deviation teaches nothing |

## 3. Out of scope for v1

Accounts and any backend; the molecule builder; free mixing; the other 16 labs; RDKit in the browser; Web Workers; a dashboard beyond a list of labs with status; element pages; post-lab question sets; hazard data pulled automatically; numeric pH shown to the learner; reloading while offline; analytics of any kind.

## 4. Architecture

A single static TypeScript web app. No server.

Stack: TypeScript, Vite, React, Tailwind v4, shadcn/ui, Three.js via React Three Fiber, Vitest.

```
src/
  chem-data/    curated JSON, TypeScript types, derive functions, validator
  engine/       seeded RNG, ion bookkeeping, reaction rules, pH solver, titration model
  mechanisms/   authored timeline data + pure state function
  app/          React UI, 3D scenes, lab benches, routing, progress storage
scripts/        build-time helpers (fetch PubChem SDFs once, generate mechanism keyframes)
```

Rules:

- `engine/`, `chem-data/`, and `mechanisms/` never import React, Three.js, or the DOM. An ESLint `no-restricted-imports` rule enforces this.
- `engine/` never calls `Math.random` or reads the clock (lint rule). All variation comes from a seeded generator (mulberry32) passed in explicitly.
- `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `WebTransport`, `RTCPeerConnection` and `navigator.sendBeacon` are banned in `src/` by lint, and the build runs the linter. All chem-data is bundled; the Inter font is self-hosted. "Offline" means no network requests after first load.
- Every engine model has Vitest tests before its UI is built.
- `app/` depends on the other three folders; they never depend on `app/`.
- Routing uses a hash router, so deep links work on any static host without rewrite rules.
- React Three Fiber is used only in Explore and Learn. Lab benches are 2D SVG with DOM controls.

The app has three areas reached from a collapsible left rail: **Explore**, **Lab**, **Learn**. The home page lists the two labs and the mechanism with status (not started, in progress, completed); one that has no page of its own yet is listed as planned, with no link and no status, as the list of labs has it. `#/lab` lists the labs; the titration lab is at `#/lab/titration`. Since the flame test lab (section 15) the home page lists three labs and the mechanism, and that lab is at `#/lab/flame`.

## 5. Chemistry data

### 5.1 The rule

Every chemistry value shown to a learner or used by a model is stored in `chem-data/` or `mechanisms/` with a source. Sources are listed once in `chem-data/sources.json` as `{ id, url, citation }`.

- A record's `sourceId` covers every value in it unless a value carries its own.
- Values that section 5.2 cites individually (experimental lengths and angles, thermodynamic values, observation rows) are stored as `{ value, sourceId }`.
- An atomic weight, an electronegativity, and a cited experimental length, angle or dihedral also store `published`: the text the source prints for the number, which keeps its digits ("1.0080"; "2.020" for the equatorial P–Cl length of PCl₅). The UI shows that text and adds the unit; the number is for calculation. `published` is absent only where the source prints no figure (the PCl₅ angles, which follow from its point group). An angle that the molecule's point group fixes is stored with that point group, whether or not the source prints a figure for it: the 180° of CO₂, the 109.471° of CH₄, the 120° of BF₃ and of PCl₅, the 90° and 180° of SF₆, XeF₄ and PCl₅. Where there is a figure the UI shows it and labels it as a cited value that the molecule's symmetry fixes; where there is none it shows the stored number and labels it as following from the molecule's symmetry, not as a cited figure. So the same kind of angle reads the same way in every molecule. Values measured from the model's coordinates are labelled as such and shown to 0.001 Å and 0.1°.
- Three kinds of field are exempt from citation, and the schema marks which is which: authored structure (formal charge, lone pairs, bond orders, 2D layout); values derived in TypeScript; and model parameters, stored as `{ value, rationale }`.

The validator runs in tests and in the build, over both folders, and fails when:

1. a field that requires a source has none, or names a `sourceId` that does not exist;
2. an ID referenced by a station or mechanism does not exist;
3. a molecule file's coordinates look like a 2D drawing: any bond to hydrogen shorter than 0.80 Å, or any bond between two non-hydrogen atoms shorter than 1.05 Å. A bond between two hydrogens has a floor of its own, 0.70 Å, since 2026-10-09: the bond of H₂ is 0.741 Å, the one real bond the first rule would refuse;
4. any authored prose string (chem-data text, mechanism text, lab primers) matches an institution-specific pattern: a location word (`room`, `building`, `cabinet`, `shelf`, `stockroom`) followed by a number or letter-number code; a course-number shape (two to four letters followed by three or four digits, excluding text that follows `CID`, `CAS`, or a citation year; letters that do not start with a capital count only when they spell a listed subject such as `chem`, because ordinary prose puts lower-case words before numbers); or a name from a configurable list. The validator's tests pin this: "room temperature", "building block", "CID 962", and "NIST 2022" must pass; "Room 214", "CHEM 1411", "chem 1411", and "cabinet B3" must fail;
5. a `published` string is not a plain decimal number equal to the number stored beside it, or a cited length, angle or dihedral has neither a `published` string nor the point group it follows from.

PubChem CIDs are stored for identity and outbound links. Nothing is fetched at runtime.

In the UI, each inspector card, station result, and energy panel has a "Sources" control listing the citations and links for the values it shows.

### 5.3 Shapes

**Reagent:** `id`, `name`, `formula`, `pubchemCid`, `form` (solution, solid, metal), `molarity` (solutions), `molarMass` (solids and metals), `appearance` (solids and metals), `ions` (species IDs and stoichiometric ratio), `hazards`, `sourceId`. Hazards are shown on the reagent's bottle card (on the titration bench, the bottle's tile; in the aqueous lab, the reagent's tile on its station). A reagent of the aqueous lab also holds `classifiedAs`, the heading over its statements, which says what they classify. A reagent whose sheet lists no hazard statement stores the signal word None and no statements, and its tile says in a sentence that the sheet lists none. A hazards record holds the signal word, the statements, the `sourceId` of the classification, and `note`, the note for the concentration used, stored as `{ value, sourceId }`, with a second source in `alsoSourceId` where the note rests on two.

**Species** (ions and products): `id`, `formula`, `composition` (element counts), `charge`, `state`, optional `solutionColor` (name and hex), thermodynamic values where a model needs them.

**Observation row:** product `id`, `color`, `texture`, `odor`, `sourceId`.

**Station:**

- `id`, the two reagent IDs, and `amounts` (mL for each solution, g for each solid or metal). Amounts are fixed; the learner does not choose them.
- `observationTools`: the eye, at every station (section 8.2), and the station's other tools. What each tool and each position of a tool shows is in `expected`.
- `equations`: curated molecular, complete ionic, and net ionic equations with states (all three null at station 5).
- `expected`: `{ precipitate: species ID or none, precipitateColor, liquidColor, colouredIons, gas: species ID or none, bubbles, odor, temperature: none | warm | hot, toolResults }`. `bubbles` is whether the gas is seen to bubble out (ammonia is not), and `colouredIons` the coloured ions left dissolved.
- `paletteSpecies` (correct species plus distractors), `hints`, `notes`.

**Element:** `symbol`, `name`, `atomicNumber`, and cited values for atomic weight, electronegativity, configuration, shell counts, ionization energies (eV), covalent and van der Waals radii, ionic radii where relevant, and display colour.

**Molecule:** `id`, `name`, `pubchemCid`, `topic`, optional `variantGroup` and `variantLabel` (for neutral and zwitterion forms), atoms (element, 3D position, 2D position, formal charge, lone pairs), bonds (atom pair, integer order in the Kekulé form, aromatic flag, optional `resonanceNote`), `geometrySource` (PubChem computed or cited experimental), optional cited experimental lengths and angles, optional `notes`, `sourceId`. Display names are authored by hand; PubChem supplies only the CID and link.

Molecule files hold curated inputs only. Oxidation state, steric number, hybridization, and VSEPR geometry are derived by pure functions in `chem-data/derive.ts` and are not stored.

**MO diagram:** molecule ID, ordered levels (label, degeneracy, electron count, bonding or antibonding), `sourceId`.

### 6.1 Library

The first library was the 31 entries below. Glycine and alanine each have a neutral and a zwitterion structure file (33 files in total), shown as one library entry with a form toggle.

- **Basics (8):** H₂O, CO₂, NH₃, CH₄, O₂, N₂, HCl, H₂O₂.
- **VSEPR showcase (5):** BF₃, SO₂, SF₆, XeF₄, PCl₅.
- **Organic functional groups (11):** ethane, ethene, ethyne, ethanol, acetic acid, acetone, formaldehyde, methylamine, ethyl acetate, acetamide, benzene.
- **Biomolecules (4):** β-D-glucopyranose (CID 64689), glycine (CID 750; zwitterion CID 5257127), L-alanine (CID 5950; zwitterion CID 7311724), urea.
- **Mechanism species (3):** H₃O⁺, HCO₃⁻, H₂CO₃.

**Since 2026-10-09 the library is 101 entries (105 structure files) in six groups.** Seventy were added, chosen to show an idea (a shape, polarity, resonance, an expanded octet, isomers, a functional group) or because a person knows them from daily life:

- **Basics (17 more, 25):** H₂, Cl₂, HF, CO, O₃, H₂S, HCN, HNO₃, H₂SO₄, H₃PO₄, and the ions OH⁻, NH₄⁺, NO₃⁻, CO₃²⁻, SO₄²⁻, PO₄³⁻ and CH₃COO⁻.
- **VSEPR showcase (8 more, 13):** SO₃, PCl₃, CCl₄, CH₂Cl₂, CHCl₃, SF₄ (seesaw), ClF₃ (T-shaped), XeF₂ (linear, five domains).
- **Organic functional groups (13 more, 24):** methanol, dimethyl ether (an isomer of ethanol), propane, butane and 2-methylpropane (isomers), cyclohexane, propene, acetaldehyde, formic acid, toluene, phenol, acetonitrile, diethyl ether.
- **Biomolecules (10 more, 14):** glycerol, L-lactic acid, citric acid, L-serine (CID 5951; zwitterion CID 6857581), L-cysteine (CID 5862; zwitterion CID 6419722), adenine, thymine, fructose (β-D-fructofuranose, CID 439709), sucrose, palmitic acid.
- **Everyday molecules (22), a new group:** caffeine, aspirin, acetaminophen, ibuprofen, vanillin, menthol, limonene, capsaicin, cinnamaldehyde, ascorbic acid, theobromine, nicotine, isoamyl acetate, methyl salicylate, benzaldehyde, geosmin, dopamine, serotonin, adrenaline, indigo (CID 5318432), 2,2,4-trimethylpentane, aspartame. Each carries one sentence that says what it is (section 5.2).
- **Mechanism species (3):** as before.

Left out, of those asked for: beryllium chloride and bromine pentafluoride, whose elements are not in the explorer's element table (11 elements; adding one takes radii from sources not read for it), so the library has no square pyramidal molecule; and the triiodide ion, for which NIST CCCBDB has no experimental geometry. No molecule has more than 50 atoms (palmitic acid).

The library page lists the entries under their group headings from the small index (`library-index.json`), not from the structure files, and has a field that narrows the list by name or formula as it is typed: a label, the count of molecules shown in a status line, a Clear button, and Escape to clear. A match is what the command palette calls one.

No salts in the library: ionic compounds are not molecules. Notes carried by individual molecules:

- **PCl₅:** "gas-phase structure", with separate axial and equatorial bond lengths.
- **H₂O₂:** the H–O–O angle of 94.8° is the 1962 measurement NIST lists; later measurements give about 100–102°.
- **SO₂:** drawn in the octet-obeying resonance form (one S=O, one S–O, formal charges +1 on S and −1 on one O), as in OpenStax Chemistry 2e.
- **HCO₃⁻:** the two unprotonated C–O bonds are equivalent in the real ion; the computed conformer shows them at different lengths.
- **Zwitterions:** the form found in water and in the solid; the model is a computed conformer.
- **SO₄²⁻, PO₄³⁻, H₂SO₄, H₃PO₄, SO₃ (2026-10-09):** drawn in the octet-obeying form, as SO₂ is: every bond from S or P to oxygen single (one S=O in SO₃), +2 on S or +1 on P, −1 on each oxygen that carries no hydrogen. The note says that both drawings are in use and that PubChem's record draws the S=O or P=O double bonds, which lowers the formal charges and gives the central atom more than eight electrons. The oxidation state, geometry and hybridization of the central atom are the same in both.
- **HNO₃:** the two N–O bonds to the oxygens that carry no hydrogen are close to equal in the real molecule, not equal: NIST lists 1.199 Å and 1.211 Å.
- **SF₄, ClF₃:** "gas-phase structure", with the axial bonds longer than the equatorial.
- **A molecule added on 2026-10-09 for which PubChem lists more than one conformer:** "one conformer of many".

### 6.2 Views

Ball-and-stick, space-filling (van der Waals radii), wireframe, and 2D Lewis. Double and triple bonds render as parallel cylinders; aromatic bonds render as delocalised. The 2D Lewis view is custom SVG drawn from the curated 2D positions and lone-pair counts.

### 6.3 Inspectors

Inspectors open when an atom or bond is selected. Beside the canvas, a DOM list of atoms and bonds shares selection with it, so the inspectors and the measure tool work by keyboard.

**Atom card**, base layer: symbol, atomic number, mass, electronegativity, valence electrons, formal charge, oxidation state, hybridization, VSEPR geometry. Expanded layer: electron configuration, ionization energies, atomic and ionic radii. For hydrogen and xenon the expanded layer also shows the emission spectrum of the isolated atom: a strip, a table of wavelengths with colour names (and, for hydrogen, the electron transition), and a note that an atom bonded in a molecule does not emit these lines. Since 2026-10-08 it also carries the note shown with every spectrum of the periodic table, on what the strip leaves out (periodic table spec, section 5.8). Strip colours are approximate; the wavelengths are the data.

**Bond card:** length, order, polarity as Pauling electronegativity difference (labelled "a rough guide"), σ/π composition. Aromatic bonds show "aromatic (delocalised), order 1.5". A bond with a `resonanceNote` is one of a resonance pair: the carboxylate C–O bonds of the zwitterions and of acetate, the two unprotonated C–O bonds of HCO₃⁻, both S–O bonds of SO₂, both O–O bonds of ozone and the two N–O bonds of HNO₃ to the oxygens that carry no hydrogen. Or it is one of a resonance set of three (2026-10-09): the three bonds of NO₃⁻, of CO₃²⁻ and of SO₃, which read "resonance set of three, order 1.33" and "1 σ + delocalised π (resonance set of three, effective order 1.33)", with the note worded for three structures and three equal bonds. Aromatic bonds are those of a benzene ring, six carbons drawn with alternating double and single bonds, wherever one occurs; a ring that holds nitrogen (nicotine, adenine, caffeine) is stored as drawn and not marked. Both bonds of the pair show "resonance pair, order 1.5" and "1 σ + delocalised π (resonance pair, effective order 1.5)", with a note beneath that says how the Lewis structure draws that bond: "The Lewis structure draws this bond as a double bond, in one of two equivalent resonance structures; the two real bonds are equal." Under Sources, the card says where the order comes from for the bond it shows: the Lewis structure as drawn for an ordinary bond, the shared π bond for a resonance pair, and the ring's shared π bonds for an aromatic bond. The stored order, the Lewis view and the 3D model keep the drawn double and single bond.

Derived values:

- **Oxidation state:** valence electrons minus (lone-pair electrons + bonding electrons assigned to the atom). Each bond's electrons go to the more electronegative atom (Pauling) and are split equally between atoms of the same element. Before that rule, since 2026-10-09: every atom of an uncharged species made of one element is 0. The two agree for H₂, O₂, N₂ and Cl₂ and not for ozone, where splitting the bonds leaves each oxygen its formal charge (+1, 0, −1) and gives its two equivalent outer atoms different values.
- **VSEPR geometry:** shown only for atoms bonded to two or more atoms; other atoms show "terminal atom". Computed from the steric number (bonded atoms + lone pairs) by lookup. A nitrogen covered by the resonance override below does not count its delocalised lone pair as a domain, so amide and urea nitrogens are trigonal planar.
- **Hybridization:** from the steric number, following general chemistry textbooks.
  - Resonance override, nitrogen only: a nitrogen with a lone pair that is bonded to an atom carrying a double bond (amide N, urea N; and, in the molecules added later, the N–H of a ring next to a C=C or a benzene ring, as in serotonin and indigo, and the ring and amino nitrogens of adenine) is sp². The planar shape is visible in the 3D model.
  - Oxygens are not overridden. The O–H and ester oxygens of acids and esters are sp³ and bent, as in OpenStax Chemistry 2e. Their card adds: "organic chemistry describes this oxygen as sp², because one lone pair is delocalised into the neighbouring C=O". The note names what the oxygen is next to: the aromatic ring for a phenol or an aryl ether, a C=C for an enol. It is given beside a double bond of carbon only: the O–H of nitric acid, next to N=O, has none.
  - Terminal atoms: a terminal atom with a double or triple bond shows its value (carbonyl O is sp², the N of N₂ is sp). Hydrogen shows "none (1s)". Any other terminal atom (halogens, singly bonded O⁻) shows "not assigned (terminal atom)".
  - Steric numbers 5 and 6 read "sp³d (textbook label)" and "sp³d² (textbook label)", with the expanded note "real d-orbital involvement is negligible".
- **Lengths and angles:** measured from the stored coordinates and labelled with `geometrySource`. Flexible molecules (ethanol, glucose, ethyl acetate) carry the note "one conformer of many".

**Measure tool:** select three atoms for a bond angle, four for a dihedral.

### 6.4 Valence display levels

1. A Bohr diagram of the selected atom, with shell counts from the stored electron configuration, labelled "Bohr model: a simplified picture".
2. Lewis dots and lone pairs.
3. Hybrid orbital lobes for sp, sp², sp³ only; molecular orbital diagrams for O₂ and N₂ only. The O₂ diagram carries a callout that the Lewis structure shows all electrons paired while the MO diagram shows two unpaired.

Lone-pair directions for levels 2 and 3 come from one pure function of the atom's bond vectors and its ideal electron geometry, with an optional per-atom override (deferred until a molecule needs one; not built in 2A). Since 2026-10-09 it covers the three shapes of five electron domains: the lone pairs of SF₄, ClF₃ and XeF₂ take the equatorial places, at right angles to the line through the two axial bonds. A square pyramid (five bonds and a lone pair) is not covered; no molecule of the library is one.

Hybrid lobes are the last item of the Explorer phase and the first to cut if the phase runs long.

### 6.5 Acceptance

- A test asserts the bundled registry contains every library ID and that every file passes the validator.
- The validator checks every atom's stored formal charge against valence electrons minus lone-pair electrons minus the sum of bond orders.
- Oxidation states sum to each species' charge.
- An expected-values table in the test suite, generated from the research table by `npm run build:expected` with hand-written named cases, covers every atom of the Basics, VSEPR, and Mechanism groups and every non-hydrogen atom of the rest (oxidation state, hybridization, VSEPR geometry; order per bond). The entries of the 72 structures added on 2026-10-09 were written into the research table by a script kept beside it (`docs/research/phase-2/build-expected-additions.mjs`), which shares no code with `derive.ts`, in one pass with no second, independent one; their named cases are in `derive.test.ts` under their own heading. It includes: H₂O₂ (O is −1); acetamide and urea N (sp², trigonal planar); the O–H oxygen of acetic acid (sp³, bent); a terminal halogen (hybridization not assigned, no geometry shown); SO₂ in the octet resonance form (S is +4, bent); SF₆ (octahedral); XeF₄ (square planar); PCl₅ (trigonal bipyramidal; angles 90°, 120°, 180°); benzene (all bonds aromatic). Atoms are matched to the table per molecule as a set, so the test does not depend on atom order.
- For molecules whose `geometrySource` is cited experimental, lengths measured from the stored coordinates match the cited values within 0.01 Å and angles within 1°.
- Lone-pair directions for H₂O and NH₃ match the tetrahedral positions within 5°. The O₂ diagram has two unpaired electrons and bond order 2; N₂ has bond order 3.
- `describeMolecule` (the text description for screen readers) is tested for three molecules. A description is seven sentences at most: where a sentence for each kind of atom would run past that (the larger molecules added on 2026-10-09), the atoms are counted by element and geometry instead.
- Every molecule's Lewis layout fits the frame of a tablet held upright (about 548 by 288 px) at no less than 30 px to a bond.

### 7.1 Setup

The primer quotes no source: for each passage it gives the location and says in its own words what the passage establishes. Equations are as they were. The labels are held to the no-quotation rule with the paragraphs they head.

The learner titrates a 25.00 mL pipetted aliquot of standardized HCl (in the flask) with ~0.1 M NaOH from a 50 mL burette, using phenolphthalein, and calculates the NaOH molarity.

**Bottles.** The lab's three bottles (hydrochloric acid, sodium hydroxide, the indicator) are part of the titration record in chem-data: name, formula, PubChem CID, hazards, and `classifiedAs`, what the hazard statements classify, in the words of the tile's heading. They are not registry reagents: the acid's molarity is seeded. There is one HCl bottle and its label is always readable.

**Seeded values.** `app/` generates a 32-bit seed when the lab is first started, stores it, and shows it in the notebook. The seed fixes, when the lab is created and never during play:

- the HCl label, 0.0850–0.1050 M, rounded to four decimal places; the rounded number is the true concentration, so the label is exact;
- the hidden true NaOH concentration, 0.09500–0.10500 M, in steps of 0.00001 M;
- per trial, the pipette's delivery: 25.00 mL plus a uniform offset in [−0.03, +0.03] mL at 0.001 mL resolution (the learner calculates with the nominal 25.00 mL);
- per trial, the burette level after filling: uniform in [0.00, 2.00] mL at 0.001 mL resolution, so the meniscus generally sits between marks.

A trial's two values depend on the seed and the trial's number only, never on what the learner did before.

The burette is graduated every 0.1 mL and read by estimation to 0.01 mL. No other noise is added. These ranges keep the equivalence volume between 20.21 and 27.67 mL and every careful titre under 27.8 mL. Volumes are held as whole numbers of microlitres (a half-drop is 25, a drop 50) and concentrations as whole numbers of their last digit, so readings, overshoot, and grading are exact; only the test for pink uses floating point. The same seed and the same learner actions always give the same readings and expected answer. "Restart lab" draws a new seed after confirmation. The exported progress file holds the seed, from which the hidden values follow for anyone who reads the source; that is accepted.

**What the bench shows.** The reading view shows the scale with the eye level with the meniscus. Parallax is not modelled; the primer explains it. The bench never states a burette level or a delivered volume finer than a whole mL. Additions are exact, so a learner who counts them can work out the titre; that is accepted.

**Colour, entries made and steps done.** (Added at the owner's request on 2026-10-06, after the owner used the finished lab on a tablet and marked up a screenshot of it to show what would help a learner.) Three things, on the Lab and Record tabs.

- **Colour roles.** A small set of named colours, each a CSS variable defined once for the light theme and once for the dark in the lab's stylesheet, in the same hue in both: a value the learner reads off the bench or the notebook and uses (the acid's label, the pipette's volume, the counts of drops and rinses, the heading that names a trial and the words that say whose result is shown, and each figure the notebook or the record holds, a dash for one not yet there excepted); the label of a field that is waiting for an entry now, and of no field that is done or cannot be used; the tick of a step done, and a result that passed and counts; a result that did not pass or has no usable titre, in the theme's own destructive colour; the flask's status words while the flask is pink, deeper once it is overshot, and plain while it is colourless or empty whatever its last addition did; and the sentence that says why something cannot be done now. A pass that does not count carries neither the good role nor the failed one. Colour is an added cue and never the carrier: every role sits on words or a mark that say the same, and the page reads the same with the colours taken off (section 11).
- **A field whose entry is made** is disabled and shows the entry: the HCl molarity, a burette reading, the NaOH molarity, the learner's average and relative deviation. Wherever the engine would still take that entry again, which the page asks of the engine's `can` and decides nowhere itself, the field's own button reads "Change". Change makes the field editable with the old entry in it and puts focus there; the notebook keeps the old entry until a new one is recorded; "Cancel", or Escape anywhere in the field's form, puts the field back as it was. A held Enter is one press: its repeats are dropped, so it does not record, reopen and record again. So the HCl molarity can be changed during a trial and between two, which is how a label miscopied in Challenge is put right; a reading until the level or the flask changes or the trial ends; and the summary at any time. The NaOH molarity cannot, because checking it ends the trial. Where the engine takes no entry, a trial that is over among them, there is no Change and the field has its one reason under it and nothing else: no refusal of an earlier entry, and no mark of an invalid one.
- **A step of the shelf that is done once and stays done is one button.** It is named for the action until the step is done ("Condition burette", "Rinse pipette with HCl", "Pipette HCl into flask") and from then for what is so, with a tick in front ("Burette conditioned", "Pipette wet with HCl", "HCl pipetted into the flask"). The tick is decoration and the words are the button's name; each is meant to be true in every state it shows in, so a pipette that drew its acid without the rinse is "wet with HCl" and not "rinsed". One is looser: "HCl pipetted into the flask" stays after the acid has been neutralised, and whether it changes is the owner's to say. Such a button is unavailable, stays focusable, and says why when pressed. The fill can be done again, so its one button says both: "Fill burette" before, and "Burette filled. Refill" with the tick after, which refills whenever the engine can fill. A burette that has run out to its last mark is not called filled: its button reads "Fill burette" again, with no tick. The counts of drops and rinses are values, not steps, and stay text.

### 7.2 Workflow

1. Read the HCl bottle's label and record its molarity in the notebook.
2. Condition the burette with NaOH, fill it, clear the tip bubble, read the initial volume.
3. Rinse the pipette with HCl, then pipette the aliquot.
4. Add 2–3 drops of phenolphthalein.
5. Titrate to a faint pink that persists; read the final volume.
6. Calculate the NaOH molarity and enter it.
7. Refill the burette and record a new initial reading before each further trial (no re-conditioning needed).

Burette readings are typed under the reading view on the bench. The notebook shows them and the titre it works out from them, and takes the HCl molarity and the NaOH molarity.

**What must be in place.** The stopcock stays closed until the burette is filled, the flask holds the aliquot and 2 or 3 drops of indicator, and an initial reading is recorded. The burette is prepared and refilled only between titrations. A recorded reading is cleared when the level it describes changes: filling, or clearing the tip bubble, after an initial reading asks for a new one. Refilling before a trial is taught, by the primer and the Guided checklist, and not forced: a trial run on what is left in the burette is an ordinary trial unless it runs out. A control that cannot be used yet says why, in both modes; the reason names what is missing and nothing else. As built there are two cases in which a press says nothing new. While the stream or a measured pour is running, the other stopcock buttons cannot be used and a press on one is dropped: the running button reads "Close stopcock". And a Record or Check button whose field cannot be used yet has the reason shown beside it all the time. From 2026-10-06 there is one press that the bench answers without the engine's word: the engine would condition a burette a second time, which empties it and changes nothing else, since a burette once conditioned is never filled dilute again. So a press on "Burette conditioned" is not sent, and is told that the burette is already conditioned and that in this lab it stays conditioned through every refill; where the engine has a reason of its own (a titration under way, a trial that is over), that is the one said.

**Ending a trial.** The final reading can be recorded only after a swirl and wait has shown the pink to last at the current volume. Adding titrant or water afterwards clears the reading and the wait. A final reading must be larger than the initial one. The initial reading cannot be taken again once titrant has run, so where it was typed wrong, which Challenge allows, no honest final reading is left: the refusal says that the flask must then be discarded. The learner may discard the flask of a trial under way and start the trial again; the glassware stays as it was. An ended trial's flask stays on the bench with its outcome until the learner starts the next trial.

**Summary.** When three trials count (7.3), the learner enters their own average molarity and relative deviation over those three; the notebook then shows its own beside them. Neither is graded.

**Stopcock:** closed, stream, dropwise (0.05 mL), half-drop (0.025 mL). In stream mode the app sends fixed-volume additions on a timer, of 0.25 mL; the engine sees only volumes. Stream is a toggle, never a held key, and a key held down adds one drop. "Run in 1 mL" and "Run in 5 mL" open the stopcock, deliver that volume in the same additions and close it, so no volume needs the learner's timing. The reading view shows no scale while the stopcock is open. Delivery stops at the 50.00 mL mark; a trial into which titrant has run, whose burette is at the 50.00 mL mark with the flask not pink, is invalid with the message "The burette ran out before the endpoint, so this trial has no usable titre. Refill the burette before you start a trial." Where it was a wash of water that left the flask not pink at the mark, the pink it thinned away may have lasted a swirl and wait, so the message says instead that the rinse thinned the pink until it no longer shows and that no more NaOH can be added to bring it back, and the result reads "Invalid: pink rinsed away".

**Plume.** Each addition makes a local pink plume that fades on swirling and lingers longer near the endpoint. The engine works out the share of the acid still in the flask that the addition neutralised, and keeps it: after a single addition that share, or a fade time worked from it, gives the titrant still needed and so the hidden molarity. What leaves the engine is the plume's status, one of three: it fades at once, it fades slowly (a share of 0.10 or more), or it persists (the mixed flask is at or above the threshold). The drawn plume fades over one of two display durations, by its status alone, and stays when it persists. The same status drives a status line ("pink fades at once", "pink fades slowly", "pink persists"), which is the only cue under reduced motion. Persistence is checked by a "swirl and wait" action that advances simulated time by 30 seconds; there is no real wait, and the status line then says what the wait found. A wash of distilled water makes no plume: after one the status line gives the flask's colour alone until titrant is added again, and where the wash or an addition undid a wait that had shown the pink to last, the bench says that the wait and any final reading after it no longer apply. A plume is the picture of an addition being made, so it is drawn only for an addition made while the bench is on the screen: a reload, which gives back the stored last addition, draws none. The status line still gives that addition's cue. The model's flask is closed, so a pink that persists on an addition is never found faded by the wait: the wait stands for the 30 seconds of a real bench, and the primer says so.

**Modes.** Guided shows a step checklist, warns before a skipped technique step (conditioning, tip bubble, pipette rinse; the burette warning is repeated at the initial reading while the burette is still dilute), prompts a re-read when a typed reading is more than 0.02 mL from the true meniscus and does not record it; the same for an HCl molarity that is not the label's, and its checklist calls the label step done only when the notebook holds the label's own molarity, so one recorded in Challenge before the mode was changed shows as the next step; and shows a "slow down" hint within 1.00 mL of equivalence, closing the stopcock the first time it shows in a trial. It never shows the expected titre or molarity. Challenge shows none of these; skipped steps and misreadings carry into the result and are named in the post-trial feedback. The mode can be changed between trials, not during one, and no trial is labelled with a mode. Burette readings are typed to two decimal places and molarities to four; any other form is refused, in both modes. A comma is not accepted as the decimal mark.

### 7.3 Model

**pH solver.** One charge-balance equation solved by bisection on pH, covering strong, weak, and polyprotic species. It returns ideal-solution pH (no activity corrections). v1 shows no numeric pH to the learner.

**Endpoint colour.** The flask's species list includes the indicator itself and dissolved CO₂. Both buffer the jump at equivalence, as they do in a real flask.

- **Indicator.** Phenolphthalein is a two-step acid (pK 9.05 and 9.50, Tamura et al. 1996); only its doubly deprotonated form is pink. The indicator solution is 0.5% weight per volume (the basis the cited listing prints, as it was read on 2026-10-04; the listing is not kept, so the build does not check the figure again; that this lab's bottle is such a solution is assumed: section 5.2), and a drop is 0.05 mL.
- **Dissolved CO₂.** The aliquot carries CO₂ at equilibrium with outdoor air (Henry's constant from the NIST WebBook; NOAA's global mean CO₂ for a stated year). The flask is closed for the length of a trial: that amount of carbon is fixed when the aliquot is delivered and only diluted afterwards. Distilled water added to the flask is taken as free of CO₂. The titrant is carbonate-free; CO₂ uptake by NaOH is primer text, not part of the model.
- **Colour.** The pink form's concentration is pink fraction × indicator moles ÷ flask volume; more indicator drops give more of it. The drawing shows nothing below `faintPinkConcentration`, then deepens with concentration and levels off, so colour first appears at the addition where "pink persists" does. The engine gives the app the pink concentration from the threshold up and 0 below it: below the threshold the figure is the flask's pH in another form. From the threshold up the figure still gives the NaOH molarity to someone who reads it out of the page and works it back, and the flask's exact volume, which the drawing also needs, gives the pipette's delivery. That is accepted (Gate A, 2026-10-05): neither makes a trial count, and a failed trial's percent error gives the same molarity by design. The app draws with both and never shows either as text. The flask is called "faint pink" from the threshold up to `faintPinkNameLimit` and "pink" from there.
- **Threshold.** Faint pink begins at `faintPinkConcentration`, a model parameter set to 1×10⁻⁶ M. The endpoint is persistent when the fully mixed flask is at or above it.
- **Constants.** The indicator's constants and strength, the drop volume, Henry's constant, the atmospheric CO₂ fraction, the carbonic acid constants, and K_w (1.0×10⁻¹⁴) are cited and never adjusted to pass tests. Only `faintPinkConcentration` is tuned to the tests. `pinkDisplayScale`, `faintPinkNameLimit` and the plume's two fade durations are presentation parameters chosen by eye; they affect no endpoint and no grade.

The endpoint acceptance test in 7.4 was proved with these constants before the phase was planned, by a spike and an independent re-implementation (`docs/research/phase-3/endpoint-spike.md`): it passes with CO₂ in the flask, for one to four drops of 0.1% to 1% indicator, and with up to three times outdoor CO₂. The phase's design run repeated it on the whole-number grid.

**Equivalence.** Overshoot, the checks before equivalence, and the Guided "slow down" hint all use the flask's own equivalence volume: the acid actually in the flask divided by the concentration actually in the burette. A technique error changes that volume; it does not make a carefully titrated flask read as overshot.

**Trial states.**

- *Invalid:* the delivered volume is more than 0.10 mL (two drops) past the flask's equivalence volume; or titrant has run into the trial and its burette is at the 50.00 mL mark with the flask not pink, whether titrant or water was added last; or the learner discarded the flask. A trial begun with the burette still at the mark is not invalid for that: nothing has run into it, and the burette can be filled. Must be repeated. An overshot flask is shown dark pink and labelled "overshot"; the dark colour comes from this flag, not from the colour model, because a careful endpoint can already be more than half as deep.
- *Valid and passing:* a persistent endpoint was reached and the learner's calculated NaOH molarity is within ±1.0% of the seeded NaOH concentration, the edge included. A trial within 1.0% passes even when technique errors are named in it, but it then does not count toward the three (below). A passing trial shows no percent error, and the engine hands the app none for it until three trials count: one such figure, with the molarity the learner typed, is the hidden molarity.
- *Valid and failing:* a persistent endpoint was reached but the molarity is outside ±1.0%. The trial shows its signed percent error and names its causes.

**The typed molarity.** The learner types the molarity to exactly four decimal places, once per trial. It is accepted, in both modes, only when it is their recorded HCl molarity × 25.00 mL ÷ their recorded titre, rounded to the fourth decimal place. At an exact tie, where the fifth decimal place is a 5 with nothing after it, either neighbour is accepted, because rounding a half up and rounding a half to even are both taught; 9 of the 47 868 label and titre pairs that give a result in range are ties. (The owner's decision said "correctly rounded" and did not settle the tie. The phase's plan put it to the owner as its question Q1, and the owner answered on 2026-10-04 that both neighbours are accepted.) Anything else is refused and nothing is marked. In particular a value cut off after the fourth decimal place instead of rounded is refused wherever it is not also a rounded value, which it is only at an exact tie, and the sentence shown says to round and not cut the number off. The check uses only numbers the learner typed, so it gives nothing away.

**Which trials count.** The signed percent error of a failed trial lets a learner work out the hidden molarity, and a later trial could then be passed by typing a reading the burette does not show. So a passing trial counts toward completion only if both typed burette readings were within 0.02 mL of the true meniscus and the recorded HCl molarity is the label's. Nor does it count when a technique error is named in it (burette not conditioned, tip bubble, pipette not rinsed; the owner's decision at Gate A, 2026-10-05): a result within 1.0% does not show that the technique was sound. A passing trial that does not count is shown as passed and not counted, and its feedback says why: the rule, each cause, and, where a technique error is among the causes, that mistakes can push a result in opposite directions and cancel and that a small one may not move it far. No trial that does not count releases the true molarity or a passed trial's percent error.

The learner may run any number of trials until three count. The lab is then completed: no further trial is run, and Restart starts a new run. The true molarity is shown on completion, to five decimal places, the value graded against. Relative deviation is the mean absolute deviation divided by the mean, in parts per thousand; the notebook's figure is worked from the average rounded to four decimal places, as the learner is told to work it, and shown to one decimal place. It is displayed, not graded.

**Technique errors.** Each is a deterministic consequence of what the learner did or skipped. Magnitudes are model parameters, deliberately exaggerated so each error fails grading on its own at every seed; feedback names the cause. Together they need not fail: a wet pipette pushes the result up and a dilute burette or a tip bubble pushes it down, so a trial with two of them can land within 1.0%, and so can a trial run on what is left of a bubble after part of it ran out into a discarded flask. Such a trial passes and does not count (above). What is left of a bubble can be cleared before the next trial's initial reading, so a learner who puts the technique right is never held up by it. Three things here are not true to a bench, and the documentation says so. Every technique error is larger than a bench gives. The 0.60 mL tip bubble is more air than a burette's tip holds, and it escapes evenly over the first 5 mL delivered, where a real one leaves at once. And an unconditioned burette stays 2.0% dilute through every refill, where a real one dilutes less each time. Honest mixing, taken as what is left of the dilute titrant after one trial topped up with fresh, would leave a second trial about 1% dilute, on the grading line, so the same mistake would fail at one seed and pass at another.

| Error | Effect in the model | Result |
| --- | --- | --- |
| Unconditioned burette | NaOH in the burette diluted by 2.0%, through every refill, until the burette is conditioned | Titre reads high; calculated molarity low |
| Tip bubble not cleared | A 0.60 mL bubble forms when the burette is filled from empty. Not cleared, it escapes evenly during the first 5 mL delivered, so the meniscus falls 0.60 mL more than was delivered. It does not return at a refill; conditioning empties the burette, so the fill after it makes a new one | Calculated molarity low |
| Pipette not rinsed with HCl | The first aliquot drawn with the wet pipette is diluted by 2.0%; drawing it wets the pipette with acid, so later aliquots are not | Titre reads low; calculated molarity high |
| Meniscus misread | Reading typed to 0.01 mL, compared with the true position within ±0.02 mL | Not recorded, and a re-read prompt (Guided); carried into the result and named, and the trial does not count (Challenge) |
| HCl label miscopied | The molarity recorded is not the label's | Not recorded, and asked again (Guided); carried into the result and named, and the trial does not count (Challenge) |
| Distilled water added to the flask (10 mL at a time, at most 30 mL a trial) | Dilutes the flask only | The equivalence volume and the expected answer do not change (a misconception check) |

### 7.4 Acceptance

1. **Solver:** within 0.01 pH of an independently computed exact solution, with constants pinned in the test, for 0.0100 M HCl (2.00), 0.10 M acetic acid (2.87–2.88), 0.10 M H₃PO₄ (about 1.63), 0.10 M acetic acid with 0.10 M sodium acetate (pH equals the pinned pKa), and 1×10⁻⁸ M HCl (6.98, with K_w = 1.0×10⁻¹⁴).
2. **Titration curve** (HCl and NaOH only, no indicator or CO₂): within 0.01 pH of the closed-form strong acid/strong base solution at every point more than 0.5 mL from equivalence; the volume at which the computed pH crosses 7.00 is within 0.01 mL of the stoichiometric value.
3. **Endpoint:** a careful run is stream, in fixed steps, to within 2.00 mL of equivalence, dropwise to within 0.20 mL, then half-drops until persistent, all on the microlitre grid. For seeds 1–100, at 2 and at 3 drops of indicator, the flask is below `faintPinkConcentration` at every addition before equivalence, the persistent endpoint appears between V_eq and V_eq + 0.05 mL, and the trial is not flagged as overshoot.
4. **Endpoint, whatever the grid offset:** at every corner of the seeded ranges, and for every flask a learner can make (either dilution error, 2 or 3 drops, up to 30 mL of water), the excess titrant at which the mixed flask reaches the threshold is more than 0 and at most 0.025 mL.
5. **Grading:** a calculated molarity at +0.9% passes and at +1.1% fails; one at exactly 1.0%, either side, passes.
6. **Typed molarity:** a molarity is accepted only with exactly four decimal places, and only when it is the recorded HCl molarity × 25.00 mL ÷ the recorded titre rounded to the fourth place, either neighbour at an exact tie. A value one unit beyond an accepted one is refused; so is the cut-off value wherever it is not also a rounded one. A refusal marks nothing.
7. **Honest trial:** a trial within ±1.0% whose initial or final reading was typed more than 0.02 mL from the true meniscus, or whose recorded HCl molarity is not the label's, or which has a technique error named in it, is passed and does not count, and its outcome names the reason. A reading exactly 0.02 mL off counts. For seeds 1–100, a first trial with an unconditioned burette and an unrinsed pipette, one with a tip bubble and an unrinsed pipette, and a trial run on what is left of a bubble partly run out into a discarded flask never count. Trials that do not count never complete the lab and release neither the true molarity nor a passed trial's percent error; the third that counts does, and no trial can be started after it. From every such state a learner who then conditions the burette, clears the tip and pipettes with the pipette now wet with acid reaches three trials that count.
8. **Technique errors:** for seeds 1–100, each of the first three errors alone moves the calculated molarity in the stated direction by more than 1.5%, fails, is named, and a careful run on that flask is not flagged as overshoot. An unconditioned burette still fails after a refill and passes once conditioned; a wet pipette and an escaped bubble leave the next trial unaffected.
9. **Distilled water:** adding 10, 20 or 30 mL leaves the equivalence volume unchanged, moves a careful endpoint by at most one half-drop, and never changes whether a careful trial passes. A fourth addition is refused.
10. **Trial endings:** a trial is overshot as soon as the delivered volume is more than 0.10 mL past the flask's equivalence volume. A trial into which titrant has run, whose burette is at the 50.00 mL mark with the flask not pink, is invalid, also when water was added last; a trial begun at the mark stays open and its burette can be filled. A discarded trial is invalid and the next begins with the glassware as it was. No state a learner can reach leaves an open trial that cannot be ended.
11. **Modes:** in Guided, a reading more than 0.02 mL from the meniscus and an HCl molarity that is not the label's are refused and nothing is stored; in Challenge both are stored as typed. The mode cannot be changed from a trial's aliquot or initial reading until the trial ends. In an open trial that holds neither, the mode can still be changed, so a Guided check of the initial meniscus can be carried into a Challenge trial. That check reaches the initial reading only and tells nothing about the hidden molarity; it is accepted.
12. **Reproducibility:** the same seed and the same learner actions give identical readings and expected answer; a trial's seeded values do not depend on earlier trials.
13. **Resume:** a lab reloaded from storage after every action, each stream addition included, ends in the same state as one never reloaded.

### 8.1 Engine

For a station, the engine:

1. Tallies moles of every ion and solid present from the station's fixed amounts and the reagents' concentrations and molar masses.
2. Applies the rules. Each acts on dissolved ions and on solids:
   - insoluble ion pairs form a precipitate (from a per-ion-pair solubility table);
   - H⁺ with CO₃²⁻ or HCO₃⁻ forms CO₂ gas;
   - NH₄⁺ with OH⁻ forms NH₃;
   - H⁺ with OH⁻ forms water and releases heat;
   - a metal with H⁺, by the activity series, forms H₂ gas and the metal ion and releases heat. The activity series holds only the entries v1 uses (Mg above H₂).
3. Respects the limiting reagent. Spectator ions keep their colour: Cu²⁺ stays blue over white BaSO₄ whichever reagent is limiting.
4. If no rule fires, reports no reaction; only the blended reagent colours show.

A tube holds exactly two reagents with no later additions, so one ordered pass is sufficient. The engine exposes only the ten stations; it has no entry point for arbitrary pairs.

**Engine output:** which rule fired, product IDs and amounts, the limiting reagent, the temperature rise, and which coloured ions remain. The temperature rise assumes no heat loss and water's heat capacity and density, and is labelled idealised.

**Curated per station:** the three equations, the liquid colour name, and colours, textures, and odours (from the observation table). In ionic equations only dissolved strong electrolytes are split into ions; solids (CaCO₃, Mg, precipitates), H₂O, gases (CO₂, H₂), and NH₃ are written as whole formulas.

## 9. Mechanism timeline

### 9.1 Model

A mechanism is authored choreography. The scene state is a pure function `state(mechanism, t)` of the scrub position `t` in [0, 1]: atom positions, bond orders, electron-pair paths, active species, energy cursor, camera target, and explanation text. Scene components draw from `state` only, with no smoothing between frames, so scrubbing in either direction gives identical frames. The learner-controlled camera is the one exception.

**Data.** A mechanism has a fixed actor list (one stable `atomId` and element per atom for the whole timeline) and a keyframe at every step boundary, giving every actor's position and the bond list with orders. `state` interpolates positions between keyframes with a named easing; a bond whose order changes is drawn as partial. Keyframes are generated by a build script from a small authored file that places library species and maps library atom indices to actor IDs. Only the water molecules that take part in a step are explicit; bulk solvent, hydration shells, and the bubble stage are a non-atomistic backdrop.

As built, a step also has keyframes inside it wherever its choreography needs one: the timeline has fifteen, of which seven are at chapter boundaries. A keyframe gives, besides the positions and the bonds, what the actors make up there (each library species with its actors in its record's atom order, and each monatomic ion), which of those species are held together as one named unit (the two ions of one unit of the solid, until it has come apart), and what the camera frames (a point and a radius). The authored file names, for each keyframe, one actor of each species the camera is to hold, and the build gives the camera the smallest sphere that holds the centre of every atom of those species, so that nothing framed is cut by the edge of the picture. An actor can name the chapter it enters at: the record still places every actor at every keyframe, and the scene leaves out what has not been added yet (revised at the deep review of the phase, 2026-10-08, with what follows on units and on names). The authored file (`docs/research/phase-5/choreography.json`) places a species by three anchors, where one of its atoms is, which way a second points and which side a third is on, and not by a matrix: the move is a rotation and a shift, so no distance or angle inside the species changes. A species stays where it was put until one of its atoms is placed again. The build refuses a choreography in which a species is twisted out of its library shape at a chapter boundary, in which the scene's charge changes, in which a step's bonds broken and formed are not the difference between the bond lists at its two ends, in which two atoms sit on or pass through each other, or in which an actor enters apart from the rest of its species or its unit, or after a chapter that is about it.

**Step record:** time range on the track, bonds broken, bonds formed, electron paths, `deltaH` and `deltaG` (standard-state, each cited or marked as derived), optional `activationG` (cited, or the marker "schematic"), camera target, explanation text at `intro` and `expanded` depth, real timescale label, optional prediction question.

As built, the record differs from that list in these ways. An energy is stored with its value, whether it is worked out directly from cited values or derived, the method (formation values, an acid constant, a remainder, or the Eyring equation) and the sources it rests on; the build works each one out from the cited values in `docs/research/phase-5/mechanism.json`, and none is typed in. `deltaH` is null for a step that has no enthalpy of its own, and the next step's then names both steps as the ones it covers. `activationG` can also be a derived value, which step 3's is. A bond that is there before and after a step with another order is listed apart from the bonds broken and formed. Each end of an electron path is a lone pair on one atom or a bond between two. The camera is in the keyframes, not in the step. The timescale label is stored with its source, or with the reason it has none. A step names the change its formation values were taken over, and carries its own notes. Every chapter, a bookend and the prologue too, has its range, its two depths of text and the list of actors it is about.

**Features:** chapters with deep links (`?step=proton-transfer`); a non-linear track with each chapter's real timescale as a label; camera auto-framing that the learner can override and that resumes on release; beaker bookends at the start and end. The timeline is a native range input and announces on chapter change only.

**Modes.** The mechanism has the same Guided/Challenge selector as the labs. Challenge pauses before key steps to ask "What happens next?"; Guided skips the pauses. The mechanism is completed when the learner has reached `t` = 1. Beside the mode is "Start again", which asks first and then puts the run back at the start of the track with nothing answered, in the mode it was in (added at the deep review, 2026-10-08: clearing all progress in Settings was the only way before).

`state` gives the atoms that are in the scene at `t` and the species they make up there, each marked where the chapter is about it, and the electron paths only during the move of a step in which its bonds change. The species are named from the bonds as they are at `t`: a bond counts once it is more than half formed and until less than half of it is left, so a species becomes another half-way through the move in which its bonds change, and not at the keyframe that ends it (as first built it was the species of the last keyframe passed, and a hydronium ion was called one until the last frame of the proton's move). A unit of the solid is held by no bond and is one thing by the same rule: until the move that parts its two ions is more than half done. The state's energy cursor is for drawing: between two levels a curve is a drawing choice, so nothing prints the cursor's value (section 9.4).

### 9.2 HCl + NaHCO₃ → NaCl + H₂O + CO₂

Solid NaHCO₃ is added to hydrochloric acid. Track order: beaker bookend, prologue, steps 1–4, beaker bookend.

- **Prologue** (chapter `prologue`, deep-linkable, labelled "before mixing", no energy values): what is already in the bottle. Hydrochloric acid is fully ionised: H₃O⁺ and hydrated Cl⁻.
1. **Dissolving:** NaHCO₃ separates into hydrated Na⁺ and HCO₃⁻. Timescale: seconds, depending on particle size and stirring.
2. **Proton transfer:** H₃O⁺ gives its proton to HCO₃⁻, forming H₂CO₃. Timescale: picoseconds to nanoseconds.
3. **Decomposition:** H₂CO₃ splits into H₂O and dissolved CO₂ through a water-relayed proton shift. Timescale: tens of milliseconds; the slow step. (As built the label reads "tens of milliseconds; the slower of the two steps that change bonds": steps 1 and 4 are labelled in seconds, beside which "the slow step" read as a mistake. Changed at the deep review.)
4. **Gas escapes:** dissolved CO₂ gathers into bubbles and leaves; Na⁺ and Cl⁻ remain as spectators. Timescale: seconds.

**Energies.** The overall process is NaHCO₃(s) + H⁺(aq) → Na⁺(aq) + H₂O(l) + CO₂(g), with ΔH = +31.4 kJ/mol and ΔG = −42.4 kJ/mol at 298 K from the NBS tables.

- In the NBS tables, "H₂CO₃(aq)" means CO₂(aq) + H₂O. That entry must not be used for the true H₂CO₃ molecule shown in steps 2 and 3.
- Step 2 uses the cited true pKa of H₂CO₃. Step 3 is the NBS total for H⁺ + HCO₃⁻ → CO₂(aq) + H₂O minus step 2, labelled as derived.
- If no separate enthalpy for true H₂CO₃ can be cited, the enthalpy curve shows steps 2 and 3 as one segment.
- A barrier with no citation is drawn schematically and labelled "not to scale".
- Step 1's ΔG is slightly positive at standard state. It carries the note "slightly uphill at 1 M; it dissolves because the acid removes HCO₃⁻ as it forms". (As built, since the deep review: "Slightly uphill when both ions are at 1 M. It dissolves all the same: the ions start far more dilute than that, and the acid removes HCO₃⁻ as it forms." The first wording read as if the solid would not dissolve in water without the acid, which it does.)

The energy panel plots free energy as the main curve with enthalpy alongside. Its note reads: heat is absorbed in dissolving the solid and releasing the gas; the reaction proceeds because escaping gas increases entropy. This leads into Gibbs free energy.

Monatomic ions (Na⁺, Cl⁻) are drawn as spheres sized by cited ionic radii: each at the same fraction of its ionic radius as an atom's ball is of its van der Waals radius, a quarter, so that every ball in the scene is at one scale (as first built an ion was drawn at its whole ionic radius beside atoms at a quarter of theirs, and a sodium ion looked as large as a hydrogen carbonate ion; changed at the deep review, 2026-10-08). Polyatomic species use the library's 3D records.

The literature values for true H₂CO₃ are identified and cited before the mechanism phase's plan is written.

**As built.** `docs/research/phase-5/sources/README.md` says how each value was read, what is worked out from what, and what could not be sourced. In short:

| Step | ΔG, kJ/mol | ΔH, kJ/mol | Barrier |
| --- | --- | --- | --- |
| 1 Dissolving | +2.325, from the NBS tables | +18.70, from the NBS tables | none: not one move over a barrier |
| 2 Proton transfer | −19.92, from the pKa of the carbonic acid molecule, 3.49 (Pines and others, 2016) | none of its own | schematic: drawn 10 kJ/mol high, a drawing parameter, and labelled not to scale |
| 3 Decomposition | −16.419, derived: the NBS total for steps 2 and 3 less step 2 | −7.64 for steps 2 and 3 together, from the NBS tables | about 66 kJ/mol, derived by the Eyring equation from a lifetime of about 60 ms |
| 4 Gas escapes | −8.379, from the NBS tables | +20.291, from the NBS tables | none |

The steps sum to +31.351 and −42.393 kJ/mol, and nothing was tuned to that. The pKa was measured at 20.5 °C and is used at 25 °C with no correction. Step 3's barrier is a value, so it is drawn to scale and labelled as derived, where the list above foresaw only a cited barrier or a schematic one. No enthalpy of the carbonic acid molecule is cited, so the enthalpy curve shows steps 2 and 3 as one change. The timescale labels of steps 2 and 3 rest on the same paper; those of steps 1 and 4 have no source and are stored with that reason. The radii of the two ions are Shannon's for six neighbours, checked through a transcription and not in the paper. One water molecule is in the scene from the first chapter, because it has a part in step 3; no other water is drawn. The solid is not in the scene until step 1 begins: "Before mixing" shows the acid alone, as a close group, and the unit of the solid comes down into the picture from above it. The sodium ion parts from the hydrogen carbonate ion by an ångström and a half within step 1 and drifts on during step 2. The water made in step 2 moves off upward during step 3. In step 3 one O–H group of carbonic acid turns to face the relaying water in four moves of 45 degrees before the two protons move, in one move. In step 4 the carbon dioxide leaves up and to the right, where nothing else is, and is out of the picture before the step ends. Where the atoms are between and around the reacting species is this project's choreography and not a computed or measured path; the first chapter's text says so, and step 3's says it of how the hydrogen crosses.

The energy panel's note is the record's own and is longer than the sentence above: it also says what enthalpy, entropy and free energy are, and that a change runs by itself when G falls. It is followed by the sum of the four steps and by what standard conditions are.

### 9.3 Acceptance

- **Continuity:** at every step boundary, `state` just before and just after gives the same atom positions within a small tolerance. This is of every atom that is in the scene on both sides: an atom that is added at a boundary is where its keyframe has it from that boundary on, and nothing leaves the scene at one.
- **Bond bookkeeping:** each bond in a step's bonds-broken exists before the step and each bond in bonds-formed does not; each step's bond list at its end equals the list at its start, minus bonds broken, plus bonds formed. The set of atoms and the total charge are identical at every chapter boundary, and every species' connectivity there matches its library record. This is of the record, which places all fourteen actors at every keyframe; the scene does not draw the six of the solid before it is added, and what it leaves out it leaves out as whole species.
- **Energies:** the summed step `deltaH` and the summed step `deltaG` (steps 1–4) equal +31.4 and −42.4 kJ/mol within 0.5 kJ/mol.
- **Deep links:** each chapter's link opens at that chapter's start.

### 9.4 The page as built

The page is `#/learn/hcl-nahco3`, loaded lazily. The Learn page lists it with its status, and Home and the search link to it. This section says what was built and where it differs from 9.1 and 9.2; `docs/research/phase-5/build-record.md` gives the reasons.

- **The head** has the title, the mode in one line that opens, "Start again" beside it once a run is stored, the button of the energy panel, the periodic table in a new tab, and the notices of section 10. There are no tabs, no primer and no Start: the page opens on the timeline.
- **The scene** is drawn from `state(mechanism, t)` and the element table at every render, with nothing eased or kept between two positions. Atoms of a molecule are balls of the explorer's size and colours, bonds are sticks, and a bond whose order is between two whole numbers is its whole lines and one dashed line, thinner and more broken the less of it there is. The two ions are balls at the same scale, with the symbol and charge written beside them once each is a species of its own, in ink that reads in either theme; one helper line under the scene says that every ball is drawn much smaller than the atom or ion it stands for, so that the bonds can be seen. An electron pair on its way is a curved arrow with two dots on it: a flat mark on the picture, drawn over everything else, which starts at the edge of the atom a lone pair is on or at the middle of the bond the pair comes from, ends at the middle of the bond the pair becomes or at the edge of the atom it stays on, and bows round that atom's ball. All the arrows of a move are shown together, five in step 3. The two bookends are a drawn beaker, laid over the scene, whose powder and bubbles move with the timeline.
- **A molecule or an ion is named** in a callout when it is pointed at or tapped in the scene. A list beside the scene gives the same names, those that take part in the chapter first; focusing or tapping a name puts the callout on its molecule in the scene. Until the solid has come apart it is one thing with one name, "unit of solid sodium hydrogen carbonate, NaHCO₃", in the callout, the list and the scene's description, so that the page does not answer step 1's question; before it is added it is not listed at all.
- **The camera** frames what the keyframes give: at a chapter's start, the species the chapter is about, whole, in a sphere no wider than 4.5 Å (as first built, up to 11). Step 1 is the exception: the solid is out of the picture when it begins and comes into it. A learner can turn and zoom it with a pointer, and their view is kept as the timeline moves: the direction they look from, and how much closer or further than the chapter's own distance. What the camera looks at stays the chapter's, so the action is followed. A "Reset view" button, shown once the scene has been turned or zoomed, gives the chapter's own view back. 9.1 says the framing resumes on release; as first built it came back whenever the timeline moved, and the owner, using it, found that a zoom lost at every move of the slider could not be worked with (2026-10-08).
- **The timeline** is under the scene: Play or Pause, Previous and Next named by the chapter each goes to, a native range input over the whole track in steps of 0.005, and the seven chapters marked under it, each as wide as its share of the track. A share is too narrow for a name, so a step's mark shows its number, and the real timescale of the step the timeline is in is one line under the track; a screen reader is given every chapter's name and timescale in the list. Play takes one minute for the whole track, which is a pace for the eye and says nothing of the reaction. Previous in the first chapter goes to the start of the track and Next in the last goes to its end, which is where the timeline is completed. Under the reduced-motion setting there is no Play, and one line says why.
- **The chapter in words** is one chapter at a time: its heading, its short text, the longer text in a closed disclosure, and a link to the chapter that can be followed or copied.
- **The energy panel** floats over the page, as the labs' calculator does, and stays open while the timeline moves. It draws free energy as the heavier, whole curve and enthalpy as the thinner, broken one, each named on the chart, with a cursor where the timeline is, the four steps marked, and in words on the curve which barrier is not to scale and what is derived. Under the curves is what the step the timeline is in changes, with where each value is from, and the note of 9.2 on step 1. Closed until they are opened are a table of all four steps, the panel's notes, how each value was worked out, and the sources. A step's notes are in this panel and not with the chapter's words, since each is about an energy. While Challenge keeps any step's name back, the panel gives figures and no words about them: the notes, how each value was worked out and the sources each answer a question, and wait, with one line that says so, until every question is answered.
- **No figure off a drawn curve is printed.** The cursor marks a place. Every energy the page or the scene's description gives is a step's own whole change or a sum of whole steps. The description gives a step's own change, at the start of a chapter the total of the steps before it, and after the last step the total of all four; between steps 2 and 3 it gives no total of enthalpy.

Reaching the end is said once, in Challenge with how many predictions were right.
- **A deep link** opens at its chapter's start and saves nothing. The place is the run's own from the learner's first action, when the address drops the link, so that a reload comes back to where the learner was.
- **The scene in words** (`describeMechanismState`) is in a closed disclosure under the timeline and is the picture's description for assistive technology. At a bookend, where the page draws a beaker and no atoms, the words are the chapter, the picture of the beaker and, after the last step, the totals. It changes with the position and is not a live region: only the chapter is announced. ## 10. Progress

Guest-only. Progress is stored in `localStorage` as JSON. Each lab, the mechanism, and preferences have their own entry with its own version, so a change to one resets only that one.

- **Per lab:** seed, mode, status, recorded readings and observations, answers, and the current trial's engine state as plain data. Titration progress is saved after every learner action and every stream addition, so a reload resumes the current trial at the delivered volume, with the stopcock closed. The titration entry holds the seed and what the learner did and typed; what the seed fixes and what is judged from it (pass or fail, percent error, causes) are worked out on reading, so a stored record cannot disagree with its seed, and a change to the model's values raises the entry's version. Nothing is saved until the learner starts a lab, so opening its page leaves the home page saying not started. Aqueous progress is saved with each action the engine takes. Its entry, `lab:aqueous`, holds the mode, the status and, for each of the ten stations, whether the tube is mixed, which tools have been used, the observation last checked and the equation last checked in each form; there is no seed, since the stations are fixed. Whether an observation or an equation is right, and whether a station is done, is worked out on reading and stored nowhere, so a change to what a station expects raises the entry's version. What is chosen or built and not yet checked is not stored, and neither is the station shown. The flame test lab's progress (section 15) is saved in the same way, with each action the engine takes. Its entry, `lab:flame`, holds the mode, the status, what the loop carries now, the closing question's answer as last given and, for each of the six stations, what the loop carried when it was last held in the flame there, which of the flame and the strip's lines and bands have been looked at since, and the observation last recorded with what the loop carried when it was made; there is no seed. Whether an observation counts, whether it is right and whether a station is done are worked out on reading, so a change to a flame's colour, to a line or a band or its rank, to the answer ranges or to the closing question raises the entry's version. What is chosen and not yet checked, the entry of the list that is shown, whether the spectroscope is being looked through and a warning that is showing are not stored. The calorimetry lab's progress (section 16) is saved in the same way, with each action the engine takes. Its entry, `lab:calorimetry`, holds the seed, the mode, the status and, for every run of each of the three parts in order, the step of the logger at which the lid was put on and at which the stirrer was started, whether the logger has been started, the step after whose reading the change was started, how many steps the logger has taken, which readings have been looked at, the worksheet's entries as they were made, and whether the worksheet has been checked. The masses and temperatures of a run, which metal the piece is, every reading of the logger, whether an entry follows, whether a run counts and why not, and whether a part is done are worked out on reading from the seed and from what was done, and stored nowhere, so a change to the draw, to the cup's model, to a value a result is held to or to the stored shape raises the entry's version. (One such change was made with the version left at 1: on 2026-10-10 a typed temperature came to be held to the logger's exactly, where a tenth of a degree either side had been taken. The lab had not been released, so there was no stored run to judge differently.) What is typed and not yet entered, the part that is shown, the reading last looked at and a warning that is showing are not stored.
- **Mechanism:** mode, status, last position, and the first answer given to each prediction, saved with each action the engine takes. Playing is shown frame by frame and written where a frame enters a chapter and where playing stops, however it stops, the page being left or closed among them (as first built it was written at every frame; changed at the deep review, 2026-10-08). A page closed in a way the browser gives no notice of comes back at the start of the chapter it was playing in. Whether an answer was right is worked out on reading, so a change to the track or to a question's answers raises the entry's version. Nothing is saved by opening the page or by following a deep link.
- **Preferences:** theme and reduced motion (each System, On, or Off; System is the default and follows the operating system), valence display level.

Stored records are plain data with no browser-specific types, so the same shapes can later be written to a database unchanged. If an entry fails to parse or has an unknown version, that entry starts fresh and the old value is kept under a backup key instead of being deleted; a later broken value gets its own numbered backup key and never replaces an earlier one. Where the store is too full to take the backup, the old value stays under the entry's own key and nothing is saved over it: that entry's progress lasts for the session only, with the notice below showing, until a save finds room to make the backup first. The home page shows an entry that is not JSON, or is of another version, as not started. It reads an entry's version and status and nothing else, because holding a record to a lab's own shape would mean loading the lab, which the home page does not do (section 4). So an entry of the right version that the lab's page will refuse is shown as the status it claims, in progress or completed, until that page has been opened; the page sets it aside, and the home page says not started from then on. That is accepted (Gate A, 2026-10-05). A lab page that starts fresh because its entry was set aside says so, in a status paragraph, on that visit, until the page is reloaded or a new run is started: that a saved run could not be opened in this version, that it was kept, and that the export includes it (added at the deep review, 2026-10-05; before, the learner saw a lab that had never been started and no word of the run). A lab page open in two tabs of one browser takes the record the other tab saves at the moment it is saved, with its stopcock closed, so that neither tab saves an old record over a newer one; a value the page's version cannot read is left where it is, and an entry removed in the other tab leaves this one not started (added at the deep review). Two actions made in two tabs within the moment the browser takes to tell the other are still last save wins. If the browser refuses a save part-way through a session, the settings page and each lab page say that progress will last only for that session. The notice stays while any entry's latest save was refused; a later successful save of a different entry does not clear it, and "Clear my progress" does (built with the titration lab, the first activity that saves more than preferences).

A settings page offers "export my progress" (downloads the JSON) and "clear my progress".

## 11. UI and accessibility

As in the original doc: calm, card-based layout; the 3D viewport or lab bench in the centre; in the explorer the atom and bond list sits to its right and the inspector runs across the page below it, its cards side by side where there is room, with the text description and the element details open by default; a lab page in three tabs, primer, lab and record (section 7.1), with the working part of the lab notebook beside the bench where the page is wide enough for both and below it otherwise, and the record of trials on a tab of its own (the aqueous lab has no docked notebook: its Lab tab is the ten stations, one at a time, and its Record tab the table of what was recorded at each; section 8.5; the flame test lab's is the same, with six stations and a closing question; section 15.6; the calorimetry lab's Lab tab is its three parts, one at a time, each with its worksheet in the part's own column, and its Record tab every run of each part; section 16.7); the mechanism's timeline under its scene, with the chapter's words beside the scene where the page is wide enough and below otherwise (section 9.4); light and dark themes; Inter with tabular numerals; design tokens as CSS variables in the Tailwind theme; a Ctrl+K command palette over molecules, labs, and the mechanism.

The theme and the reduced-motion setting in effect (the stored preference, or the system's) are applied before first paint by a short inline script in `index.html`, so that the dark theme never flashes light. The build writes that script from the app's own definition of the preferences entry (its key, version and allowed values), and a test holds its decision to the app's for every kind of stored value; missing, corrupt or unreadable storage follows the system, and storage that can be read but refuses writes keeps the stored preferences, in the script and in the app alike. `color-scheme` is set for both themes, so the browser's own controls match.

Accessibility is designed toward WCAG 2.1 AA:

## 15. Flame test lab (added after v1)

Asked for by the owner on 2026-10-08, when the periodic table's emission spectra were extended to every element and it became plain that a flame's colour is not simply the atom's strongest lines. It is the first lab beyond the two of v1, and section 3's "the other 16 labs" is one fewer. It uses the lab shell of sections 7 and 8 (Primer, Lab, Record; Guided and Challenge) and the rule for hazards of 5.2.

### 15.1 Set-up

Six solutions, each 0.1 M and each a chloride: barium chloride, calcium chloride, copper(II) chloride, potassium chloride, sodium chloride and strontium chloride. One metal loop, a spot plate with a well of each solution, a burner's flame, distilled water, and a hand spectroscope with a wavelength scale from 400 to 780 nm. The learner observes the six; there is no unknown to identify, and no cobalt glass (the primer says in a sentence what it is for). Nothing is seeded: the lab is the same every time.

### 15.2 At a station

One salt at a time, in the shell's list with Previous and Next. A station is a short column of cards:

1. **The bottle**: the solution, what it looks like, its hazards.
2. **The loop**: "Clean the loop" (rinsed in distilled water and held in the flame until the flame shows no colour), then "Dip the loop" in the station's well. The loop's state is said in words.
3. **The flame**: "Hold the loop in the flame". A drawn flame takes the colour. The learner looks at it as they look at the tube of section 8: pointing at it, focusing it or tapping it says its colour in a callout, and that look opens the first question.
4. **The spectroscope**: "Look through the spectroscope" shows a strip against its scale with what the flame gives: sharp lines and broad bands, each where its source puts it. Each is looked at in the same way, and its callout says where on the scale it is, its colour, and whether it is a line or a band. Looking opens the other questions.
5. **What you saw**, in choice boxes: the colour of the flame; where on the scale the brightest thing is (ranges of wavelength to choose from); and whether that brightest thing is a sharp line or a broad band.

Guided has the hints, and what a correct observation holds, each in a closed disclosure (the hints stood open at first; the same five at every station were tiring to read, and they were closed at the review of 2026-10-09). Challenge shows neither until the learner has recorded an observation of their own that counts: one made with a clean loop (as first built, any recorded observation brought them, so a careless dip and a guess bought the answers; changed on 2026-10-08, before the screens). Feedback says which answers are not right and never the right one.

**The technique that matters is a clean loop.** A loop carries what it was last dipped in until it is cleaned, and a loop that has only been handled carries a trace of sodium. In the flame every salt on the loop shows: the spectroscope has the lines and bands of each, and sodium's yellow hides the other colours of the flame. An observation made with a loop that was not clean does not count, whatever was recorded, and its feedback names the cause; the station is done again with a clean loop. In Guided a warning is raised before a loop that is not clean is dipped, with a way to go on anyway, as the titration lab's warnings are. The size of the handling trace is a model parameter, made large enough to show, and the primer says so.

When all six are done, one closing question in both modes: all six bottles are chlorides, so what gives each flame its colour? The lab is complete when the six observations are correct, each made with a clean loop, and the closing question is answered correctly.

### 15.3 Data and model

For each salt, stored with sources that were read: the colour of its flame (a name, and a colour to draw it in); and what is seen in the spectroscope, as a list of features, each a sharp line (one wavelength) or a broad band (a range), with its colour, how prominent it is among the salt's features, and what gives it: the metal's atom, or a molecule formed in the flame, named. Atomic lines are NIST's, from tables saved as the emission spectra's are. Where a band's limits cannot be read from a source, the feature says where the source puts it and that it is approximate. Hazards follow 5.2: the supplier's sheets by default, the most restrictive official document where one is stricter, cited; disposal is left to the laboratory's own rules and local regulations.

The engine is pure and holds no chemistry of its own: the loop's contents, what the flame and the spectroscope show for them, the check of an observation, and the lab's stored progress (mode, per station what was looked at and recorded and whether the loop was clean, the closing answer, status).

Each station's notes, shown once it is done, say what gives the light there, and for calcium, strontium, barium and copper that the flame's colour comes mainly from molecules, whose light that element's card of the periodic table (linked) does not show. As first written the notes, the primer and the closing question's feedback said that the flame is not the colour of the lines on the card. The cards do not bear that out: six of the nine lines on calcium's card are orange or red and its flame is orange-red, and three of the six on strontium's are red and its flame is red. Since the review of 2026-10-09 each says what is so: the card shows lines of the atom alone, the atom's line of the strip among them where the strip has one, and what colours the flame is mostly the molecule's light, which the card does not show.

As built, the record and the engine differ from 15.2 and from the paragraphs above in these ways, each for the reason given; `docs/research/flame/README.md` says how every value was read and what could not be sourced.

- **A pair of lines is one feature.** Two lines of one salt closer than 5 nm are stored and shown as one sharp line, the stronger with its partner beside it: sodium's two yellow lines and both of potassium's pairs. A hand spectroscope does not separate them, and the 5 nm is a parameter of the model. The callout says that it is two lines too close together to tell apart.
- **When the questions open.** A look at the flame opens the first question. The other two open only when every line and band on the strip has been looked at, since which is the brightest cannot be said before all have been seen.
- **What a callout says.** Where a line or a band is, its colour, which of the two it is, and also how bright it is beside the others on the strip, so that the brightest can be told without seeing the picture. It never says what gives it: that is the station's notes', once the station is done.
- **Brightness is the instruments', not the eye's.** A feature's rank follows what its sources' instruments recorded, or the relative intensity NIST lists, and never a table of measured intensities, of which none was found. Potassium's deep red pair is ranked first on that ground, at the edge of what an eye sees. The primer says so.
- **Where on the scale.** The second question is answered from six ranges that cover the scale with no gap, each boundary at least 5 nm from the brightest feature of every salt.
- **A band without limits.** A band whose sources give only where it is brightest is stored at those positions, marked approximate, and drawn 5 nm wider on each side; its callout says that its limits are not given.
- **What the strip leaves out.** Bands a source names and gives no place for (those of SrCl, of copper oxide), or that are spread over most of the scale or lie inside another (BaO, BaCl), are not on the strip. Each is said in a sentence at its station, shown with the notes.
- **A loop that carries several salts.** With sodium among them the flame is sodium's yellow, from a source. Without sodium the flame is called by the colour of each salt, in the order they came onto the loop, and is drawn in each side by side: the model's own rule. On the strip every salt's lines and bands are shown as that salt alone gives them, and the model does not rank one salt's light against another's: a callout then says "one of the brightest". Each line and band is counted along the strip by its middle, so that a line that stands inside another salt's band is counted where its button lies (at first each was counted by where it begins, and on such a loop the count, the Tab key and the buttons disagreed). The primer says that what such a flame is drawn and called as is this lab's rule.
- **The trace on a handled loop** shows as fully as a dip in the sodium chloride solution.
- **The closing question** has five choices: the chloride, the gas, the loop, the metal, the water. A wrong one is told why it cannot be the answer and can be changed; attempts are not limited, there or at a station.
- **One more saved table.** The emission spectra's tables stop at 700 nm, so one more response of the NIST database, for potassium from 700 to 780 nm, is kept with this lab's sources.
- **Hazards.** The rule of 5.2 as the owner refined it on 2026-10-08: the stricter document wins where what it says is about the substance. Each bottle's note is three short paragraphs and can rest on more than two documents.
- **What is stored.** The loop's contents now; for each station what the loop carried when it was last held there, the looks made since, and the observation last recorded with what the loop carried when it was made. Whether that loop was clean is worked out on reading.

### 15.4 Primer

Short topics in the shell's paged primer, those to read first marked: what a flame test is; light from atoms (an electron falling between levels gives light of one wavelength: a line); molecules in a flame (broad bands, and the four metals whose flame colour is mostly theirs); the loop (cleaning it, what an unclean one does, sodium everywhere, and cobalt glass in a sentence); the spectroscope and how to read its scale; safety (the burner, the salts, and that disposal is decided by the laboratory's own rules).

### 15.5 Acceptance

- For each salt, a clean loop gives the stored flame colour and the stored features and nothing else.
- A loop that was not cleaned gives the features of everything on it; with sodium on it the flame is sodium's yellow; an observation made so does not count and its cause is named; Guided warns before the dip.
- Every stored feature has a source; every atomic line's wavelength is the saved table's digits.
- No state a learner can reach leaves them unable to go on; the stored record round-trips; Challenge shows nothing of what is expected before the learner records an observation that counts.
- The descriptions in words of the flame and of the spectroscope's view are tested for every salt.

### 15.6 The page as built

Built on 2026-10-08 and 2026-10-09, straight through, as the aqueous lab's screens were (section 13), on the shell and the station pieces of sections 7 and 8. The route is `#/lab/flame`, loaded lazily; Home, the list of labs and the command palette show it with its status.

- **Lab tab: one entry at a time.** A list of seven: the six stations, each with how far it has come in words beside a mark (not started; started, once the loop has been held in the flame there; recorded with a loop that was not clean; recorded, not correct yet; done), and the closing question, which says that it opens when the six are done. Previous and Next are named for where they go. The list is the shared paged list. It is beside the station only from 58rem of bench, later than the primer's topics, so that the station beside it still has the strip's full width; below that it is behind its button.
- **A station is a short column of cards,** each there when the engine has a use for it. The bottle: the solution's tile, with its name, what it looks like in words, its bottle drawn with its label and, for the one coloured solution, its liquid in that colour, and its hazards, whose note is drawn as three short paragraphs. The loop: a drawn loop, its state in words in a status line, "Clean the loop" and "Dip the loop", and a sentence that says what the one step of cleaning is. The flame, once the loop carries the station's solution: "Hold the loop in the flame", then the drawn flame. The spectroscope and the three questions, once the loop has been held. The notes, what the strip leaves out, a link to the card of the station's metal on the periodic table, in a new tab, and the station's Sources, once the station is done and not before: each of them says, or names a paper that says, what gives the light.
- **Guided's warning** is drawn in the loop's card when a loop that is not clean is dipped. It takes focus, as the titration lab's does, and is the same component. "Go back and clean it" puts focus on Clean; "Dip it anyway" dips and puts focus on Dip. Any other press on the loop's or the flame's card drops it, and so does a change to Challenge. Once dropped it is raised again only by Dip: as first built a station kept that its warning had been raised and drew it whenever a dip there would warn, so a warning left unanswered came back by itself after a change of mode and back, or when the loop, cleaned at another station, carried another salt again (put right at the review of 2026-10-09).
- **The flame is explored.** It is drawn about 200 px tall on a dark card in both themes, in the colour the record stores for what is on the loop, with the burner's own pale cone inside it and its edge drawn, so that a flame of no colour would still be a flame; a loop that carries two salts and no sodium gives a flame drawn in both colours side by side. One button lies over it. A mouse pointer over it, keyboard focus on it or a tap looks at it: a callout beside it says its colour in words, the same words go to a status line for a screen reader, and the first question opens. The flame flickers five times, for under five seconds, where the reduced-motion setting allows, and is still under it.
- **The strip is explored.** "Look through the spectroscope" shows, on a dark card, a black strip over a scale from 400 to 780 nm with a mark every 20 nm and a number at every 100 nm and at 780. A broad band is a stretch that fades at its two ends, drawn short of the strip's top and foot. A sharp line is a thin stroke at its wavelength, the strip's whole height and so taller than any band, with a dark gap either side of it and its edges drawn on the screen's own pixels; every line is drawn over every band. Each is in the colour of its wavelength, the brightest of a salt's drawn whole and the others fainter by rank: 1, 0.75 and 0.55 of full strength. (As first built a line was a stroke with a glow about it, as tall as a band, and barium's line, 3.5 nm from the end of its band, read as the band's bright edge. Changed at the review of 2026-10-09, and the primer's card on the spectroscope says how the two are drawn, as a rule of the simulation.) A button lies over each, as tall as the strip and at least 44 px wide where the picture is at its narrowest; where two would overlap, the space between them is split, and a line beside a band has its button off-centre. A look says, in a callout over the strip that stays inside the card, where the line or band is, its colour, which of the two it is and how bright it is beside the others. The gap between the strip and the callout is part of the button, so a pointer moved up onto the callout does not lose it. Until it has been looked at, a line or a band is named, in its button and in the list under the strip, by its place in the count from the violet end and by nothing else; the page never carries the record's own name for it, which says what gives it.
- **The strip's width.** The spec asked for a strip that scrolls sideways in its card below about 560 px. As built the picture is drawn down to 440 px before it scrolls. The narrowest window that shows a bench, 768 px with the menu open, leaves it 447 px, and an upright tablet of 820 px leaves it 499: at 560 both would have had to be scrolled to find potassium's deep red line, at the far end. At 440 px the marks of the scale are about 21 px apart and every button is still 44 px wide.
- **A colour the screen can show.** The shared function that turns a wavelength into a colour fades toward 780 nm, as the eye does, and would draw potassium's pair near 766 nm almost black. On the strip a wavelength beyond 740 nm is drawn in the colour of 740 nm, so that the line the lab calls the brightest can be found. The primer says that a real eye sees that light faintly.
- **Nothing on the strip is too dim to find.** Whatever is drawn on the strip has a contrast of 3 to 1 or more with the strip's black, as a ratio of luminances. Where the colour of a wavelength at its rank's strength falls short of that, the colour is moved toward white by the fewest of 64 steps that reach it, and the strength stays the rank's. That is so for calcium's violet line and strontium's blue one, ranked third (1.5 and 2.2 to 1 as first built), for potassium's violet pair (1.9), for its deep red pair (3.0 where it was 2.96) and for the violet end of copper's band (2.5 at its middle). They are paler than the colour of their wavelengths, and still violet, blue and red. Added at the review of 2026-10-09 and measured from screenshots at four window sizes in both themes: every line 3.0 to 1 or more over two columns of pixels or more.
- **The questions** are three groups of choice boxes, each disabled, with what to look at first under it, until its looks are made, and one button, "Check observations". They are the aqueous lab's observation form, made a shared component. An observation made with a loop that was not clean is told that it does not count and why, as a reason and with no tick or cross, and a "Clean the loop" button under it cleans the loop and puts focus on Dip. A new hold of the loop is a new thing to look at: the spectroscope is closed again and the form is empty, and an observation made at an earlier hold stays the station's, in the list and in the record, until another is recorded. Where the loop has been cleaned or dipped again since it was held, the flame's card says that its pictures are of the loop as it was held.
- **Hints.** In Guided the five hints are over the questions, in the card they help with, in a closed disclosure named "Hints", and what a correct observation holds is under the questions in another. In Challenge neither is in the page until an observation that counts has been recorded, and a sentence says when they come; they are closed there too. (The hints stood open until the review of 2026-10-09.)
- **The closing question** is the list's last entry: one group of five choice boxes and "Check answer", there and disabled, with the reason under it, until the six stations are done.
- **Record tab:** a table of the six stations, with the three answers as last recorded and whether the observation counted and is correct; the closing question with the answer last given and whether it is right; and, once the lab is complete, the line that says so, which the Lab tab says too.
- **The descriptions in words** of the flame and of the whole strip (15.5) are tested for every salt. The page shows the first, as the flame's callout. It does not show the second, which names the brightest thing outright: it shows what one line or band is when that one is looked at, as section 8.5 does with the tube.
- **What the page keeps and does not store:** what is chosen and not yet checked, the entry shown, whether the spectroscope is being looked through, a warning that is showing, and what the message lines last said. A reload opens on the first station begun and not done, and on the closing question once the six are done.

## 16. Calorimetry lab (added after v1)

Suggested by the owner on 2026-10-09. It is the second lab beyond the two of v1. It is built without the owner's department notes for it: its three parts are the usual ones of a first-year coffee-cup calorimetry lab, and each is the owner's to change. It uses the lab shell (Primer, Lab, Record; Guided and Challenge), the notebook and typed entries of section 7, the pictures that are explored of section 8, and the rule for hazards of 5.2.

### 16.1 Set-up

A coffee-cup calorimeter: two foam cups, one inside the other, a lid with a hole, a stirrer, and a temperature probe whose readings a logger plots against time, one reading every 15 seconds. Three parts, each with an idea of its own:

1. **Neutralisation.** 50.0 mL of 1.00 M hydrochloric acid and 50.0 mL of 1.00 M sodium hydroxide solution. The heat given out for each mole of water formed.
2. **Dissolving.** A weighed portion of solid ammonium nitrate, about 4 g, in 50.0 mL of water. The heat taken in for each mole dissolved.
3. **A metal's specific heat.** A weighed piece, about 50 g, of an unknown grey metal (aluminium, iron, zinc or tin, by the seed), heated in boiling water whose temperature is read, then put into 50.0 mL of water in the cup. The metal's specific heat, and from it which metal it is.

A run's starting temperatures, masses and the bath's temperature are seeded, so that no two runs share their numbers; the same seed and the same actions give the same run. The seed is drawn in the app.

### 16.2 A run

A part is a short column of cards:

1. **The bench**: what is used, with its hazards, and the balance's reading where something is weighed.
2. **The cup**: drawn, with its state in words. "Put the lid on", "Stir", "Start the logger", then the one action that starts the change (pour in the second solution; add the solid; add the hot metal), and "Run on" to let time pass, 30 seconds at a press. No clock runs: time is a count the engine is handed. In Guided a warning is raised before the change is started with the lid off or the stirrer still, with a way to go on anyway.
3. **The graph**: temperature against time as the logger draws it, a point for each reading. The graph is the picture that is explored: pointing at a point, focusing it or tapping it says its time and its temperature, and a look at the readings before the change and at the highest or lowest after it opens the notebook's first entries. It is also said in words.
4. **The notebook**: a worksheet of entries in the order they are worked out. For parts 1 and 2: the starting temperature; the highest or the lowest temperature reached; the change in temperature; the heat the cup's contents took in or gave out, in joules; whether the reaction gave heat out or took it in (a choice); the moles; and the heat for each mole, in kJ/mol, with its sign. For part 3: the heat the water took in; the specific heat of the metal, in J/(g·°C); and which metal it is (a choice).

A temperature typed must be the reading the logger shows, to the tenth of a degree. (As first specified a tenth of a degree either side was taken as well. Changed by the owner on 2026-10-10: a look at a reading gives it to 0.1 °C, so nothing is estimated, and with the tenth either side a run could have every entry taken and then not count; section 16.7 says more.) Every other entry must follow from the learner's own earlier entries, correctly rounded, as the typed molarity of 7.3 must. Guided checks each entry as it is made and has the relation it uses ready in a closed hint; Challenge checks them together at the end. Feedback says which entry does not follow and never the value.

**A run counts** when its temperatures are the logger's, each entry follows, the lid was on and the cup was stirred throughout, and its result is within the tolerance of what the model gives for that run. A run that does not count says why. One run that counts completes a part; a part can be run again, with new numbers. The lab is complete when all three parts are.

### 16.3 Model

The engine is pure and deterministic. The heat of a run is the moles reacted or dissolved times a stored enthalpy, or for the metal its mass times its stored specific heat times its fall in temperature. The cup's contents warm or cool as their mass times the specific heat of water, with solutions taken as 1.00 g/mL: the same idealisation the learner's own arithmetic uses, said as one in the primer. The temperature approaches its end value over a mixing time, short when stirred and long when not; and it exchanges heat with the room, slowly with the lid on and several times faster with it off, so that the curve reaches a peak and drifts back. The learner takes the peak. The calorimeter itself takes up no heat, and the hot metal reaches the cup at once and dry: both idealised, and the primer says what a careful bench does about each.

Magnitudes are model parameters with rationales, chosen so that a careful run is within tolerance at every seed and each technique error alone (the lid off; not stirred) puts a run outside it at every seed, as 7.3's are. No cited constant is adjusted to make that so.

### 16.4 Data

Enthalpies of formation from the NBS tables, as elsewhere; the specific heats of the four metals from a source that can be cited, given for a gram as worked out from the value for a mole; molar masses; the specific heat of water. Hazards by 5.2: the 1 M acid and base carry the records of section 8's lab; solid ammonium nitrate and the four metals get their own; boiling water and a hot piece of metal are in the primer's safety topic.

### 16.5 Primer

Short topics, those to read first marked: temperature and heat; giving out heat and taking it in, and the sign of the change; specific heat, and heat as mass times specific heat times the change in temperature; the calorimeter and what it assumes; reading the graph; from heat to heat for each mole; a metal's specific heat; safety.

### 16.6 Acceptance

- For seeds 1 to 100, a careful run of each part counts, and its result is within tolerance of the stored value: the neutralisation's heat for each mole, the ammonium nitrate's, and the metal's specific heat, which also picks the right metal out of the four.

## 17. Group I cations lab (added after v1)

Asked for by the owner on 2026-10-09, the first of a set of labs taken from the owner's department's lab directions. Those directions say what is set out for a lab and not what a learner does, and some of what they say is out of date: by the owner's word the labs and their outcomes are what matters, and the particulars are corrected and brought up to date here. So the procedure is the usual scheme for these three ions, and each choice in it is the owner's to change. It uses the lab shell (Primer, Lab, Record; Guided and Challenge), the test tube that is explored and the observation form of section 8, and the rule for hazards of 5.2.

A real bench of this lab holds lead, mercury, silver and chromate. That is the case for a virtual one, and the primer's safety topic says so.

### 17.1 Set-up

Qualitative analysis: finding which ions a solution holds by what they do, not how much there is. The three ions are silver, Ag⁺; lead, Pb²⁺; and mercury(I), Hg₂²⁺. They are the ones whose chlorides do not dissolve in cold dilute acid, which is what sets them apart from every other common metal ion.

On the bench: hydrochloric acid, 6 M; distilled water and a bath of boiling water; acetic acid, 6 M, and potassium chromate solution, 0.5 M; ammonia solution, 6 M; nitric acid, 6 M; blue and red litmus paper; a centrifuge. The samples are made from 0.1 M solutions of silver nitrate, lead nitrate and mercury(I) nitrate.

Two parts:

1. **The known.** A sample that holds all three ions, worked through the scheme so that every positive result is seen once.
2. **An unknown.** A sample that holds one, two or all three of the ions, which of the seven by the seed. The learner works it through the same scheme and says which ions it holds.

### 17.2 The scheme

Five steps, each on a tube the step before it left:

1. **Precipitate the group.** Hydrochloric acid is added to the sample: a white solid, the chlorides of whichever of the three are there. The tube is centrifuged and the liquid poured off.
2. **Take the lead out.** Hot water is added to the solid and the tube is heated in the bath: lead chloride dissolves in hot water and the other two do not. The tube is centrifuged and the hot liquid poured off into a second tube.
3. **Confirm lead.** Acetic acid and potassium chromate go into the second tube: a yellow solid, lead chromate, if lead is there. With no lead the liquid is yellow, from the chromate, and stays clear: a yellow liquid is not a yellow solid, and the tube's picture marks which is which.
4. **Part silver from mercury.** Ammonia is added to the solid left by step 2. Silver chloride dissolves, as a colourless ion of silver with ammonia. Mercury(I) chloride does not dissolve: it turns grey to black, which confirms mercury(I). The tube is centrifuged and the liquid poured off into a third tube.
5. **Confirm silver.** Nitric acid is added to the third tube, a little at a time, until litmus shows the liquid is acid: a white solid, silver chloride come back, if silver is there.

### 17.3 A run

A part is the five steps, one at a time. A step is a short column of cards:

1. **The tube**, drawn, with its layers marked as liquid or solid, and explored: pointing at a layer, focusing it or tapping it says what is seen there (never what it is). The step's actions are beside it: add the step's reagent, heat, centrifuge, pour off, test with litmus, each offered when the engine has a use for it.
2. **What is seen**: choice boxes, opened by looking, as section 8's observation form: is there a solid, what colour, what the liquid looks like.
3. **Where each ion went** (part 1 only): a flow chart of the scheme with empty places, filled from a set of tiles, one step's worth after each step: which of the three is in the solid, which in the liquid, and as what. In part 2 the finished chart is beside the work as a map, once part 1 is done.
4. **Which ions** (part 2 only, after step 5): three boxes, any of which may be ticked.

Guided warns before a technique error and lets the learner go on, checks each observation and each placing as it is made, and has a hint ready in a closed disclosure. Challenge warns of nothing and checks a step's observations together when asked.

**A run counts** when the technique was right, each observation matches what the tube showed, and, in part 2, the ions named are the ones the sample holds. A run that does not count says why. One run that counts completes a part; part 2 can be run again, with a new unknown. The lab is complete when both parts are.

Three errors of technique, each real and each its own cause:

- **Pouring off without centrifuging.** The solid goes over with the liquid, the tube poured into is cloudy, and the run does not count.
- **Pouring off the water of step 2 without heating it.** Only part of the lead chloride has dissolved; the rest stays in the solid and is still there, white, after the ammonia of step 4.
- **Judging step 5 before the liquid is acid.** No solid forms though silver is there.

The net ionic equation of each step is shown in the notes once the step is done, with its source. It is not built by the learner: section 8's lab is where equations are written.

### 17.4 Model

The engine is pure and deterministic. A tube holds whole-number amounts of what is dissolved in it and of each solid. Each action changes them by a stored rule that has a source: the three chlorides form with hydrochloric acid; lead chloride dissolves in hot water, and in cold water as far as its solubility allows; lead chromate forms with chromate; silver chloride dissolves in ammonia and comes back with acid; mercury(I) chloride with ammonia gives a grey to black solid. Where a stored number can check a rule (an ion product against a solubility product at the bench's amounts; the lead chloride against what the water added can hold, hot and cold; the acid added against the ammonia it has to neutralise), the build makes the check and stops on a disagreement.

Simplifications, each said in the primer: a pouring off is taken to be clean, where a careful bench washes each solid; the amounts are fixed by the bench, not chosen.

### 17.5 Data

Solubility products from the Gibbs energies of the NBS tables, as elsewhere, or from another source that can be cited; the solubility of lead chloride in cold and in hot water; the formation constant of the silver ion with ammonia; what each solid and each liquid looks like; what mercury(I) chloride does with ammonia; molar masses. Hazards by 5.2 for every bottle on the bench and for the three nitrates.

### 17.6 Primer

Short topics, those to read first marked: what qualitative analysis is; solids from solutions, and what a solubility product says; the three chlorides; parting ions by a difference (hot water); complex ions (silver and ammonia); mercury(I) and what ammonia does to it; confirming tests, and a yellow liquid against a yellow solid; centrifuging and pouring off; reading the flow chart; safety.

### 17.7 Acceptance

- For the known and for each of the seven unknowns, a careful run shows at every step what its ions give and nothing else, and counts; naming its ions completes part 2.
- Each error of technique alone makes a run not count wherever it changes what is seen, and its cause is named; Guided warns first.

- Challenge shows nothing of what is expected before the observations are recorded, and nothing on the page says which ions an unknown holds before the learner has named them.
- The description in words of every tube is tested.

## 18. Le Chatelier's principle lab (added after v1)

The second of the labs taken from the owner's department's lab directions (section 17 says how those are used: the lab and its outcomes are kept, the particulars brought up to date). The directions list the bottles; the procedure is the usual one for those bottles, and each choice in it is the owner's to change. It uses the lab shell, the test tube that is explored and the observation form of section 8, and the rule for hazards of 5.2.

### 18.1 Set-up

Le Chatelier's principle: a system at equilibrium that is disturbed shifts in the direction that undoes part of the disturbance. The lab disturbs four equilibria, each in a test tube, by adding something, taking something away, heating or cooling, and has the learner say beforehand which way each will go, see what happens, and say which way it went.

On the bench: lead nitrate solution, 0.3 M; hydrochloric acid, 0.3 M, 6 M and 12 M; methyl violet indicator solution; solid cobalt(II) chloride; zinc nitrate solution, 0.1 M; magnesium nitrate solution, 0.1 M; sodium hydroxide solution, 6 M; ammonia solution, 6 M; distilled water; a bath of boiling water and a bath of ice water.

Nothing in this lab is drawn by chance: the same actions give the same tubes.

### 18.2 The four systems

Each system is headed by its equilibrium, written one way and kept that way, so that "left" and "right" mean something. Each has a short list of disturbances, done in order, each from the state the one before left.

1. **A solid and its ions: lead chloride.** Lead ions and chloride ions against solid lead chloride. Hydrochloric acid, 0.3 M, is added to the lead nitrate solution a portion at a time until a white solid forms; the tube is heated, and the solid dissolves; cooled, and it comes back; water is added, and it dissolves.
2. **An indicator: methyl violet.** The indicator's yellow acid form against its violet form and a hydrogen ion. Hydrochloric acid, 6 M, is added by drops, and the violet goes through blue and green to yellow; sodium hydroxide, 6 M, by drops, takes it back.
3. **A complex ion: cobalt.** The pink ion of cobalt with water against the blue ion of cobalt with chloride. Cobalt(II) chloride in hydrochloric acid, 12 M, is blue; water is added, and it turns pink; heated, it turns toward blue; cooled, pink again.
4. **Two hydroxides: zinc and magnesium.** Each metal ion with hydroxide ions against its solid hydroxide. A drop of sodium hydroxide gives a white solid with each. The solid is then shared among three tubes: acid dissolves both; more sodium hydroxide dissolves zinc's and not magnesium's; ammonia dissolves zinc's and not magnesium's. Zinc's hydroxide dissolves in more base and in ammonia because a second equilibrium, that of a complex ion, takes the zinc ion away; magnesium has none.

### 18.3 A disturbance

A system is its disturbances, one at a time. A disturbance is a short column of cards:

1. **The equilibrium**, as written, and what is about to be done.
2. **Before**: which way will it shift (toward the left side as written, toward the right, or not at all)? One choice, recorded and never judged: it is there to be compared with what happens.
3. **The tube**, drawn and explored as in section 8, with the one action (add, heat or cool; for an addition by drops, one press for each portion, and the tube is looked at as often as the learner likes on the way).
4. **What is seen**: choice boxes, opened by looking: the liquid's colour, whether there is a solid.
5. **Which way it went**: one choice, checked. For the three tubes of system 4 that turn on the second equilibrium, the question is instead what took the metal ion away.

Once a disturbance is done, a note says what happened and why, with the learner's own prediction beside it.

Guided checks each answer as it is given and has a hint ready in a closed disclosure. Challenge takes whatever is recorded and checks a system's answers together when asked; a system that is not right is worked again.

**A system counts** when each observation matches what its tube showed and each direction is right. There is no error of technique that spoils a run here: every change in this lab can be taken back, which is the point of it. The lab is complete when all four systems count.

### 18.4 Model

The engine is pure and deterministic, and holds whole-number amounts. What a tube shows after a disturbance comes from a stored rule with a source, and where stored numbers can decide it they do: whether lead chloride is present, from the amounts and its solubility cold and hot; the indicator's colour, from the hydrogen ion left after the acid and the base added and the indicator's stated range; whether a hydroxide is present, from the amounts and the constants of its equilibria. The cobalt system is held by rule and not by number: its colour at each of the lab's states (in concentrated acid, diluted, hot, cold) is a stored observation with a source, since no constant read covers 12 M acid. The amounts of each addition are model parameters with rationales, chosen so that what the numbers give is what the usual procedure shows; no cited constant is bent to that end.

Which disturbance gives off or takes in heat is from cited enthalpies where they can be read.

### 18.5 Data

Solubility products, formation constants and enthalpies from the NBS tables, as elsewhere, or from another source that can be cited; lead chloride's solubility cold and hot (section 17's); methyl violet's range and its colours; the colours of the two cobalt ions; what each tube shows, with a source. Hazards by 5.2 for every bottle; records another lab already holds for the same bottle are shared.

### 18.6 Primer

Short topics, those to read first marked: what equilibrium is (two changes at one rate, not no change); Le Chatelier's principle; adding and taking away; heating and cooling, and which way gives off heat; diluting; a solid and its ions; indicators; complex ions and colour; a second equilibrium that takes an ion away; safety.

### 18.7 Acceptance

- For each system, working its disturbances in order shows at each one what the stored rule gives and nothing else, and the system counts when each observation and each direction is right.
- Every rule and stored value has a source; where numbers decide what a tube shows, the build checks them at the lab's amounts and stops on a disagreement.
- A prediction is recorded before the action it is about and can be neither changed after it nor judged.
- The stored record round-trips; no state a learner can reach leaves them unable to go on.
- Challenge shows nothing of what is expected before the learner's answers are recorded; a disturbance's note is shown only once it is done.
- The description in words of every tube is tested.

## 19. Clock reaction lab (added after v1)

The third of the labs taken from the owner's department's lab directions (section 17 says how those are used). It is the first of two labs on how fast a reaction goes; the second, the iodination of acetone, is built next on the same engine. The directions list the bottles; the procedure is the usual one for them, and each choice in it is the owner's to change. It uses the lab shell, the notebook and typed entries of sections 7 and 16, the graph that is explored of section 16, and the rule for hazards of 5.2.

### 19.1 Set-up

Bromate ions, iodide ions and acid make iodine, slowly. A small, known amount of thiosulfate in the flask takes up the iodine as fast as it forms, and starch is there to show iodine. Nothing is seen until the thiosulfate is used up; then the next iodine meets the starch and the liquid turns blue at once. The time that takes says how fast the reaction was going.

On the bench: potassium iodide solution, 0.010 M; sodium thiosulfate solution, 0.0010 M; potassium bromate solution, 0.040 M; hydrochloric acid, 0.10 M; starch solution; distilled water; two flasks, one for each half of a mixture; a stopwatch; a thermometer; baths of ice water, cool water and warm water.

Three parts:

1. **Five mixtures at room temperature.** Each differs from the first in the amount of one thing, or of all, and is timed.
2. **The rate law.** From the five times: the rate of each run, the order in each of the three reactants, and the rate constant.
3. **Temperature.** The first mixture again at three other temperatures; from the four rate constants, the activation energy.

### 19.2 A run

The bench sets out the mixture: so many millilitres of each solution in each flask, 50 mL in all. A run is a short column of cards:

1. **The mixture**, as a table.
2. **The flasks**, drawn, with what has been done in words. Starch is added to one flask. In part 3 both flasks stand in a bath, and the thermometer is read, before they are mixed. Then one flask is poured into the other and the watch started, as one action.
3. **The watch and the liquid.** The watch runs and the liquid is clear and colourless until, all at once, it is blue. The learner stops the watch. The page plays the time faster than a clock would; the engine reads no clock and is handed the time. The time recorded is the time the model gives with the learner's own delay added, in true seconds, as a hand on a real watch adds it. A learner may instead have the watch stopped at the change: that run counts as any other, and the record says which way it was timed.

Two errors of technique, each real: **no starch**, so that nothing ever shows; and, in part 3, **mixing before the flasks have come to the bath's temperature**, so that the time belongs to no one temperature. Guided warns before the pour; a run made so does not count and says why.

A run can be made again; the times of the runs that count fill a table that the other two parts work from.

### 19.3 The notebook

The arithmetic is done once by hand and then by the notebook, which says that it is doing so: a learner who has worked one row is not made to work nine.

- **Part 2.** For the first run the learner works out the concentration of each reactant once the two flasks are mixed, and the rate, which is the bromate used up by the time of the change, a sixth of the thiosulfate, over the time. The notebook then fills the same four figures for the other runs. The learner gives the order in each reactant, a choice of 0, 1 or 2, from the two runs the question names; then the rate constant of the first run, with its unit chosen, and the notebook fills the rest and their mean.
- **Part 3.** The notebook fills each temperature's rate constant, its natural logarithm and one over the temperature in kelvin. A graph of the logarithm against one over the temperature, with the straight line through the points, is explored as section 16's is; the learner reads two places on the line, works out its slope, and from it the activation energy.

Entries are typed and checked as section 16's are: each must follow from the learner's own earlier entries, rounded as the primer says; Guided checks each as it is made and has its relation in a closed hint; Challenge checks them together.

A part counts when its runs count, its entries follow, and its results (the three orders, the rate constant, the activation energy) are within tolerance of what the model gives for those runs. The lab is complete when all three parts count.

### 19.4 Model

The engine is pure and deterministic and holds whole numbers. It is not this lab's alone: it takes a reaction's record (the rate law's orders, its rate constant at one temperature, its activation energy, and what ends a run) and the iodination of acetone will be a second record for it.

The rate is the rate constant times each concentration raised to its order; the rate constant follows the Arrhenius equation; the time to the change is the bromate that must be used up over the rate, with the concentrations taken as they start, which is the same idealisation the learner's arithmetic makes and is said as one. Room temperature, the baths' temperatures and a small scatter in each time are seeded, the scatter no larger than a bench's, and such that at every seed the orders come out unmistakably and a careful learner's rate constant and activation energy are within tolerance.

The orders, the rate constant and the activation energy are cited where a source that can be read gives them. A figure that cannot be sourced is a model parameter with its rationale, chosen to give the times this experiment is known for, and the lab says of it that it is the lab's own.

### 19.5 Data

The overall reaction and the reaction of iodine with thiosulfate, with the six-to-one count between them; the rate law; molar masses where a note needs them; what the liquid looks like before and after. Hazards by 5.2 for every bottle: potassium bromate above all.

### 19.6 Primer

Short topics, those to read first marked: how fast (a rate, and its unit); what a rate depends on, and what a rate law and an order are; the clock (thiosulfate, starch, and why the change is sudden); finding an order by comparing two runs; the rate constant and its unit; temperature and the activation energy; reading the graph of part 3; safety.

### 19.7 Acceptance

- For seeds 1 to 100, careful runs of the five mixtures and the three temperatures all count; the orders that follow from them are the stored ones; the rate constant and the activation energy worked from them are within tolerance of the stored values.
- Each error of technique alone makes a run not count, and its cause is named; Guided warns first.
- An entry that does not follow from the learner's own numbers is refused or marked.
- The same seed, actions and times handed in give the same lab; the stored record round-trips; no state a learner can reach leaves them unable to go on.
- Challenge shows nothing of what is expected before the entries are made; the notebook fills a row only after the learner has worked the row it copies.
- The engine holds nothing of this reaction that is not in its record: a test runs it on a second, made-up record with other orders.
- The descriptions in words of the flasks and of the graph are tested.
